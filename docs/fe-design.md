# Neige 前端设计

状态：当前产品与视觉契约。范围是 `fe/web/src` 的桌面端；小于 640px 的移动端不在当前目标内。

精确的 token、组件 API、route 组装和允许值以代码及契约测试为准：

- `fe/web/src/styles/tokens.css` 与 `styles/public.ts`
- `fe/web/src/ui/**`
- `fe/web/src/app/router/public.tsx`
- `fe/tools/styles` 与 browser/contract tests

本文只保留代码不能直接说明的产品意图和视觉取舍，不复制当前文件清单、行号或实施步骤。

对外产品语言使用 **Area / Track**：Area 沉淀长期上下文，Track 承载一条从意图走向结果的工作。内部类型、API、路由、事件与样式 token 继续使用 `Cove / Wave`；设计文档提到 Area / Track 时指用户可见概念，而不是协议重命名。

## 产品感觉

Neige 是持续变化的 Agent 工作台，不是营销站，也不是传统项目管理后台。界面要同时容纳任务、对话、执行输出和长文档，但保持安静、可扫读、可继续工作。

五条原则：

1. **行是原子。** 高频信息优先使用紧凑行；卡片只用于真的需要边界、内部布局或独立生命周期的内容。
2. **层级是预算。** 尺寸、字重、颜色、留白、边框和 surface 都能制造强调；同一区域不要同时花完多个通道。
3. **持续变化也要安静。** 运行状态主要靠文案、微弱色调和稳定位置表达，避免闪烁、跳动和装饰性动画。
4. **密度是承诺。** 首屏应展示足够多的真实工作；不能用大块空白、重复标题或无内容面板换取“高级感”。
5. **颜色必须有含义。** Accent 表示当前主动作或选择；红色表示错误/破坏；琥珀表示警告；Area 身份色只表达身份。

## 页面层级

页面注意力分四层：

| 层 | 内容 |
|---|---|
| P0 | 当前任务、主文档、当前对话、执行结果 |
| P1 | 页面标题、主要状态、唯一主操作 |
| P2 | 导航、筛选、辅助面板、次要动作 |
| P3 | 时间、来源、计数、诊断元数据 |

P0/P1 不应依靠大字号和重色块同时抢占注意力。正文与任务状态必须比 chrome 更容易读。

使用 typography、间距和对齐建立主要层级；surface 和 hairline 只负责分组。阴影只用于浮层，不用于普通卡片。

## 字体、数字与密度

- 正文使用 sans；长报告允许 serif；代码、路径和命令使用 mono。
- 标题层级优先通过字重和间距区分，不建立消费级的大字号阶梯。
- 可变数字使用等宽数字和稳定格式；零值显示为 `0`，不能用空白代替。
- 高频行使用小号或标准行高；双行只在第二行始终有真实信息时使用。
- 同类列表在典型桌面视口内应至少露出约八行。
- 不为没有生产写入方的数据预留永久空间。

## 颜色与 surface

组件只能使用语义 token，不能写主题分支或原始颜色。Light 与 Dark 是分别校准的两套关系，不是简单反相。

- `--bg`：页面背景。
- `--paper`：文档、对话框等需要连续阅读的表面。
- rail、card、chip、terminal、code 使用各自 surface。
- `--text` 到 `--text-4` 表达递减层级；最低一档不能承担必要信息。
- Error 与 warning 必须分开，不能都退化成琥珀色。
- Area 身份从固定色槽中选择，不接受自由 hex（内部 token 仍为 `--cove-*`）。

Surface 总数保持有限。需要新增 surface 时，先证明现有层级无法表达，而不是为单个组件发明底色。

## 动作

动作分四档：

| 档 | 用途 |
|---|---|
| primary | 当前 surface 唯一的前进动作 |
| secondary | 明确但非唯一的操作 |
| tertiary | 低频、局部或可发现后执行的操作 |
| destructive | 删除或不可逆动作 |

一个 surface 同时最多一个 primary。行、图标、菜单项、tab 和 cell 是组件角色，不套普通动作按钮的几何。

危险操作按成本选择：

1. 可逆操作直接执行并提供 Undo。
2. 不可逆但影响局部的操作使用普通确认。
3. 删除整个 Area 这类级联破坏使用打字确认。

危险色在静止时就要可辨，不能只在 hover 才暴露。确认按钮执行中保持原有语义颜色与宽度；busy 表示“请求进行中”，blocked 表示“前置条件未满足”，两者不能共用 disabled 外观。

## 状态与反馈

每个异步区域必须区分：

- loading：保留结构，避免布局跳变；
- empty：解释这里本应出现什么，并在有明确下一步时给一个动作；
- error：保留用户输入和上下文，给出可重试动作；
- unsupported：明确版本或能力不兼容，不能伪装成空；
- busy：控件位置和尺寸稳定，文案说明正在做什么。

运行、完成、失败等状态使用稳定词汇。图标和颜色只能辅助，不能替代文本。失败原因应尽可能靠近失败对象，不能只留神秘圆点、红叉或通用 `failed`。

状态更新不得导致按钮宽度、列表行高和主列位置跳动。Reduced-motion 下关闭非必要动画。

## Shell 与页面

应用保持一个常驻 rail 和一个主区。Rail 负责 Area/Track 导航，不承担产品详情；页头负责当前位置、主要状态和当前页面动作。

960px 以下 rail 折叠为图标条，不隐藏。桌面主区使用受控最大宽度；报告和表单各有适合阅读的 measure。右侧面板只有在它持续承载当前上下文时存在，不能留下孤立空栏。

四条主路由：

### Today

Today 回答“现在该关注什么”。显示近期议程、正在运行和需要处理的事项；不复制完整 Track 页面。没有内容时使用紧凑空态，不用大面积欢迎插画。

### Area

Area 是长期上下文边界。页面突出 Track 列表、Area notes、最近对话和创建入口。Area 身份色只用于定位，不铺成大面积主题。

### Track

Track 是主要工作面。主列承载报告/任务与核心叙事，面板列承载当前卡片、运行状态和可继续的上下文。Card board、worker output、spec 对话和报告之间应形成连续路径，避免侧栏截断、悬空工具和孤立详情面板。

### Settings

Settings 是低频表单页。按用户任务分组，标签和说明直接写清后果。About 只展示真实可得的版本信息；不存在的数据整行省略，不放占位符。

## 组件契约

### 行

行必须有稳定的点击区域、焦点样式和选中状态。主文案、状态、时间与尾部动作的位置在同类行之间一致。仅 hover 出现的动作也必须能通过键盘到达。

### 页头

页头最多承载标题、短状态和少量动作。页面标题是导航后的焦点落点。吸顶时不能遮挡被聚焦的行。

### 卡片与面板

卡片表示独立资源或生命周期，不作为普通分组默认值。卡片头只保留身份、状态和必要动作；内容区负责工作本身。面板列中的内容应在滚动时保持与主列任务的关系。

### 对话框

对话框必须：

- 捕获并恢复焦点；
- 支持 Escape；
- 将背景设为 inert；
- 为确认流程提供明确的安全动作；
- 在触发元素被删除时把焦点送到新的页面标题。

普通确认初始焦点落在 Cancel；打字确认落在输入框。执行期间 Cancel 保持可用。

### 空态与错误

区域级空态可以带一个主动作；行级空态只给短文案。错误保留原输入，说明失败原因并提供重试。不要用 toast 代替需要留在上下文中的错误。

## 无障碍

- 所有操作都有语义 role 和可访问名称；图标不能是唯一名称来源。
- 键盘顺序与视觉顺序一致；列表和菜单使用 roving tabindex，避免几十个 tab 停靠点。
- Focus ring 全应用一致，不能靠 `outline: none` 删除。
- 状态不能只靠颜色。
- 对话框、drawer 和浮层明确管理 Escape 层级与焦点。
- 真实焦点、布局、滚动和对比度必须在 browser tier 验证，不能由 jsdom 假装覆盖。

## 机器边界与人工评审

机器检查负责：

- 分层依赖与 public entry；
- token 和全局类闭集；
- 原始颜色、随意尺寸和未登记 data attribute；
- focus、dialog、button 状态等可执行契约；
- 两主题对比度与关键布局；
- route 到 API/卡片 runtime 的真实接线。

人工评审负责：

- 信息层级是否清楚；
- 密度是否合适；
- 文案是否解释真实状态；
- 页面是否出现大块无意义空白；
- 动效是否打扰持续工作；
- 产品闭环是否比 chrome 更醒目。

测试不得只检查源码字符串来证明用户行为；涉及视觉、焦点或布局的结论必须观察真实浏览器结果。

## 当前边界

- 移动端未设计。
- 对话 drawer 的产品形态仍可继续收敛。
- Managed Track 没有 remote 时，Forge/PR 的呈现需要服从工作区能力，不能假装可用。
- 新页面先复用现有词汇和层级；只有出现无法表达的真实状态时才增加 token、surface 或组件变体。
