# Planner 决策契约：功能实施计划

状态：实施总纲。用户已授权按闭环逐项推进；下文未勾选功能均不声称已实现。
代码基线：`afcd302d`，2026-09-07。跟踪入口：#1501。

本文承接《Planner 契约与执行者边界：实现方向》，采用当前代码已经具备的
attempt 模型，替代旧提案的墓碑/隐藏别名恢复方案。真源、不变量和交付协议仍以
[任务连续性框架](architecture/1501-task-continuity.md)为准；本文定义 Planner
能获得的体验、实施顺序和每项完成条件。

## 1. 需要实现的体验

Planner 收到足够判断的简报，表达更新后的计划和业务决定。系统承担版本定位、
精确执行绑定、操作重试身份、机械状态推进和文件准备；用户保留原有授权边界。
发生真实歧义时，把具体冲突交还 Planner 或相应的用户决策者。

三个核心问题必须最终形成闭环：

1. **看懂执行。** 知道当前在做什么、证据有多新、为何等待，以及何时可以介入。
2. **延续成果。** 执行失败后，保留已完成的候选工作和失败原因，能够在它上面修复。
3. **准确交接。** 下一次执行拿到指定来源、指定版本、满足消费条件的输入，
   Planner 无须编写搬运任务、猜测路径或手写 hash。

默认简报足够时不要求额外读取；存在语义疑点时，始终允许查看原始证据。
不以禁止读取、更大的业务节点或隐藏错误来达成调用数目标。

## 3. 分层与规则

| 层 | 应负责 | 不应负责 |
| --- | --- | --- |
| Planner | 业务计划、验收判断、恢复提示、分歧处置及理由 | 拼接执行编号、版本锚、幂等 key、搬运脚本 |
| 确定性适配层 | 简报组合、语义操作翻译、绑定已观察的事实、冲突分类 | 猜测业务意图、擅自授权或降低验收 |
| 内核 | 事务、权限、停止围栏、attempt、验证、调度、历史 | 把 Worker 自述直接当作已验证事实 |
| Provider | 具体执行、会话与受支持的交互能力 | 替代任务授权、内容绑定或内核验收 |

优先在真实 PlannerHarness 输入和原生 MCP 调用路径上接入。仅修改尚未承载
真实 Planner 的 AgentReactor 类型，不算交付。适配层仍调用现有受守卫入口，
不能新建旁路状态写入器。

### 3.1 简报与操作绑定

- 简报表达需决定的事项、已发生事实、正在进行的近况，并保留完整的用户意图
  与输入附件。用户取消、授权变更等不能被摘要、排序或合并掩盖。
- 按同一批有序事件及一致的事实快照构造；保留精确事件来源和执行身份。
  对固定输入确定性输出。合并必须保序、不丢事实，不要求有时序意义的事件可交换。
- 区分事实来源、证据强度与表现形式：Worker 自述、内核状态、具体机器检查、
  Planner 验收和模型摘要不能混为一个标签。机器检查只证明其覆盖内容。
- 活动的发生时间与采集时间分开表达；历史补录不算新进展。采集缺失或健康状态
  未知要明确呈现，不从沉默推导失败或自动恢复权限。
- 语义操作在内部绑定本轮已交付简报的版本、相应 attempt 和稳定操作身份。
  同一已接受操作重试/重启后沿用身份，不能因为换 turn 就产生第二次效果。
- 事实过期时返回具体冲突，不能悄悄改为当前最新 attempt。修改文档时也不能只
  换成最新 revision 后盲写；只有确认并发变化不影响编辑含义才允许机械重试。
- 不从简报的自然语言、Worker 文本或模型摘要反向解析权威身份与执行命令。
  模型只能通过经过认证的语义工具表达决定。
- 业务冲突和不支持的能力成为可行动的问题；基础设施错误保留可诊断状态，
  不能以“转成问题”为由吞掉失败或伪造成功。

“Planner 不处理字段”不等于字段消失。REST、测试和内核继续使用精确身份；
适配层负责可靠携带它们。若需要扩展持久化结构，必须明确升级/恢复语义并扫清
所有读写方，不预先承诺整个功能“无 schema 变更”。

### 3.2 状态与成果

先让语义操作使用现有生命周期规则，不全面替换 lifecycle 状态机。用户的取消、
重开、释放以及既有恢复次数限制保留；失败事实不等于可重试，Running 不等于
Provider 健康或取得了进展。

保留纯顺序依赖。文件消费需要明确的输出选择、输入位置和消费用途；不能让
depends_on 自动代表复制全部文件。失败候选可以供授权修复使用，不因此获得
普通下游消费资格。验证和消费者绑定必须指向同一不可变版本。

## 4. 功能列表与顺序

每项先写明确验收，再进入实现。只有一个当前实现项；其余保持待办。
允许一个功能由连续的小 PR 完成，但接口骨架、只增加提示词或模块测试通过，
不能独立证明完整体验交付。

| 顺序 | 功能 | Planner 预期体验 | 初始范围与完成条件 |
| --- | --- | --- | --- |
| F1 | 恢复决策简报 | 失败/停止条件变化后直接知道发生什么、为何能或不能恢复 | 仅现有恢复支持的任务；无需额外拼接读面即可判断等待、申请授权或恢复 |
| F2 | 语义恢复 | 表达 Recover(key, reason)，系统兑现决定 | 绑定 F1 对应事实；一次精确、授权、可重放的同 key 恢复；返回实际结果 |
| F3 | 长任务近况 | 判断继续等待还是处理明确阻碍 | 先一个 Provider、一个长命令；正在执行/结束/采集未知可区分；不新增日志管线 |
| F4 | 单文件准确交接 | 声明产物输入，B 自动拿到 A 被验证的那个版本 | 一个 Provider、一来源、一输出、一消费者；无搬运任务或临时路径拼接 |
| F5 | 失败候选修复 | 根据失败原因继续已有工作 | 复用 F4 的绑定/准备机制；一个候选、一次显式修复、同一验收要求 |
| F6 | 语义计划编辑 | 按任务 key 修改计划或验收 | 先少数明确字段；保留作者、块身份、并发变化和已 claim 合同边界 |
| F7 | 其他语义决定 | Accept/Reject 等不要求协议字段或手工状态边 | 每个动词独立补前置事实、权限和结果闭环；Finding 处置待真源支持 |
| F8 | 跨轮草稿区 | 保存尚未定稿的判断、待办和工作笔记，不挤占公开进度正文 | 独立于 F1/F2；跨轮/重启保留、访问权限明确、写入不造成自唤醒 |
| F9 | Provider 能力接入 | 同一业务操作得到明确的支持/不支持结果 | 按闭环补 workspace/resume/steer/report 能力；不先全面搬迁所有 Codex 引用 |
| F10 | 有界反思与非代码任务 | 需要整体重审时进入反思，支持一种非代码场景 | 前述基本闭环稳定且草稿区可用后各做一项；触发有界、可停、不靠无条件定时唤醒 |

F1+F2 是首个产品目标：“失败 → 简报 → 一个恢复决定 → 后续事实”。
F1 单独完成时，只能记为“决策上下文闭环”，不能声称已经实现语义恢复。
F3 不必等待完整 F4/F5；F4/F5 也不必等待 F6–F10 或完整 Provider 抽取。

## 5. 首个产品目标的具体范围

从当前已支持的 auto-declare Planner 自有任务恢复开始。选择可证明旧执行已停止、
符合现有恢复次数与原合同限制的场景；拒绝分支仍覆盖用户所有权、declare-and-wait、
未停止、过时 attempt、撤回/合同变化和终态前提。

预期过程：

1. 已授权任务失败，系统把失败依据和“正在清理，尚不能恢复”送入简报。
2. 停止与 Operation 收尾完成后，简报说明当前允许的动作，以及重试会使用新空
   工作区、旧文件仅保留为证据。不会暗示自动继承候选。
3. Planner 表达恢复决定；适配层使用这份简报对应的身份调用既有恢复入口。
4. 系统报告请求已接受、等待/准备、失败或完成等实际事实，不把 receipt 当成开工。
5. 重放相同决定不创建第二个 successor；并发变化导致明确问题，未读到的新执行
   不会被误操作。新的业务授权仍由既有权限规则决定。

F1 实现时先核实信息在真实 turn 输入中何时组合、如何与事件队列及重放一致；
F2 实现前必须解决“已交付简报—本次工具调用—精确执行”之间的可靠绑定。
不能以读取此刻最新 task 来替代这项绑定，也不能从渲染后的简报文字提取它。
如果绑定跨越持久化边界，需要先落独立的小设计及迁移/旧会话行为说明。

当前审查已发现 F2 的具体缺口：MCP 调用身份有 session/thread，但没有可信的
本轮简报或操作身份；现有 IssuedInputSegments 是会被清除的展示元数据，也在
turn/start 返回后才写入。因此不能把它或“当前 active turn”当成迟到调用的归属
证明。F2 必须解决发送前持久化及调用方可靠携带绑定这两端。

F1 第一版据此限定为已有 isolated failure settlement 的决策简报：包含原执行
身份、失败依据、清理状态、**当前 Planner actor**的恢复能力、证据入口与空工作区
重试限制。消除为恢复资格而额外查询 plan.list 的必需步骤；原有精确恢复接口仍
保留，涉及报告编辑时仍遵守相应读取约定。通知相关性使用的 User 权限不能当作
Planner 的恢复权限。快照资格必须标明执行时重查，不能冒充永久授权。

首轮不包含失败候选继承、自动业务重试、全量计划重写、全量 lifecycle 派生、
全 Provider 统一或后台反思。失败期间用户输入仍正常进入原有对话路径。

## 6. 后续三个闭环的验收

### F3：长任务活动

给 Worker 一条有开始、持续执行和结束证据的长命令。Planner 简报能区分：
进程/会话被记录为运行、观察到命令活动、正在等待什么、命令已结束。
停止采集时显示事实不足，不把旧活动伪装成新活动；换 attempt 后不沿用旧近况。
第一版不凭“多久没输出”自动重试，也不加入无界模型轮询。

### F4：准确交接

A 停止写入 → 捕获候选版本 → 在该版本上验证 → 满足所声明消费条件 →
B claim 时绑定该版本 → Operation 准备并核验输入 → 启动 B。

修改或删除 A 原工作区后，B 输入仍等于被验证的版本。快照缺失、完整性失败、
准备失败或撤回授权时 B 不启动；重启不改用最新目录。来源编号由内核提供，
不依靠 Worker 自报。初始仅支持明确的一种工作区和普通文件，拒绝不支持的类型。

### F5：失败成果修复

A 已写出有用内容后失败 → 证明写入停止 → 保留失败候选和具体原因 →
Planner 决定修复 → 同 key 新 attempt 获得选定候选、原有精确输入及修复提示 →
按不变的要求重新验证 → 后续才可消费。

修复任务能证明原有工作得到保留；旧失败及其验证记录不改写。修复读取失败候选
不等于接受它，验证器产生的新文件也不能偷换成消费者的输入版本。复杂合并冲突、
多来源、多候选和全局 Finding 传播留作后续。

### F8：跨轮草稿

Planner 写入一段待办/暂定判断 → 后续轮次与重启后仍能读到 → 决定成熟后显式
更新公开计划或报告。草稿默认不出现在面向用户的进度正文，不占该正文的字数
额度，但自身有明确资源上限；用户管理、导出和删除遵循 Track 的授权规则。
测试 Planner 专用读写、Worker 不可访问、报告渲染隔离、跨轮/重启保留，以及
写入不会触发自身的 report_edited 唤醒循环。

草稿不是任务、验收或权限真源，也不能承载 F2 必须防篡改的动作绑定。不以保存
Provider 内部推理来实现工作笔记。该项单独设计存储/访问契约，不加入 F1/F2。

## 7. 验证、指标与交付节奏

- 功能回归经真实 authoring、harness 输入、工具、调度或 Operation 入口；
  外部 Provider 可在明确边界替换为测试实现，不复制生产算法。
- 缺陷先 RED；关键权限、精确绑定、重放/不丢消息断言做有预测红集的生产 mutation。
  不为普通文案或每项枚举断言机械增加 mutation；修复后重跑失效检查。
- 简报测试固定事件顺序、事实快照与时间输入，验证确定性、来源、无损合并和原文入口。
  可选模型摘要移除后，确定性需决定事项及授权集合不变。
- 每个非机械改动经两路独立完整审查；修正后两路复审。执行相关局部 gates，
  CI 负责广域验证，适用时跑隔离的 Tier1；不在共享主机运行真实 Tier2。
- 真实产品实验单独计数业务节点、恢复节点、机械补救、Planner 读写和外部介入。
  记录源版本、执行身份、失败假设和局限；实验结束清理仅自己启动的服务。
- 文中历史 13/6 节点、协议错误与读取次数仅作问题线索。为每个支持场景建立当前
  对照，目标是没有协议性补救和外部关键纠错、常见决定无需预读；不承诺所有任务
  固定两次调用或所有 Provider 的模型决定序列逐字一致。
- 主任务负责总纲、范围、实验、集成和账本；主要实现委派，工作区独占。用户已授权
  PR 与 CI 绿后 squash 合入，仍须满足仓库审查规则。保持完整合并描述。
