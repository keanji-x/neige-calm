# F2：语义恢复的简报与调用绑定

状态：实施设计，F2 尚未交付。基线 `bd45581b`。
承接 [Planner 功能实施计划](design-1501-planner-contract-roadmap.md)。

## 目标和范围

Planner 只填写任务 key 与恢复理由。系统确定该决定所依据的简报、精确 attempt
和操作身份，再调用既有恢复事务。旧调用不能被重新指向后来出现的执行。
第一版限定新建的共享 Codex Planner 会话，以及既有权限允许的恢复场景。
不会增加恢复次数、继承失败文件、自动重试业务或改写 Provider 整体架构。

本机安装的 Codex 0.153.4 通过 app-server generate-json-schema --experimental
生成的协议声明了 thread/start 的 dynamicTools，以及 item/tool/call 请求的
threadId、turnId、callId、tool、arguments。该能力仍标记 experimental；
本设计先验证真实使用路径，不把协议声明等同于产品接通。

现有 Neige MCP 身份只能定位 session/thread；展示用 IssuedInputSegments
还会被清除。两者都不能证明迟到调用属于哪次简报。放弃按 session 查找最新 offer
或最新 attempt 的方案，也不从自然语言提取绑定。

## 两个连续交付项

### F2-A：双向工具请求传输前置

在现有 Codex app-server 客户端接入最小的 server request/response 路径：

- 带 method 和 id 的请求先按请求处理，不能与本客户端待回复 RPC 的相同 id
  混淆。整数和字符串请求 id 原样回传。
- 工具请求保留 Provider 提供的 threadId、turnId、callId 和参数。它们是之后
  绑定的输入，不单独授予恢复权限；工具 arguments 不能覆盖外层身份。
- 响应只能写回请求所属的连接实例，不能在断线重连后写进新连接。
- 请求交给独立且有界的处理入口。慢处理不能占住 reader，阻塞 turn/start
  响应或其他通知；队列容量、处理超时和不支持方法的结果必须明确。
- 传输层不执行恢复、不选择最新任务、不创建业务幂等身份。已有普通 RPC 和通知
  路径继续工作；未注册处理者时明确拒绝请求，不能永久挂起。

验收：真实客户端对测试协议对端完成工具请求→处理→原连接回应的往返；覆盖
双向相同 id、字符串 id、慢处理同时普通 RPC 完成、断线/取消与未知方法。
如在这项加入工具声明入口，也必须验证其精确 wire shape，并默认不改变其他线程。
此项是 F2 前置；没有恢复业务效果，不标记 F2 完成。

### F2-B：持久化绑定与一次语义恢复

数据契约分为简报发送记录和不可改绑的 turn 记录：

1. 发送前持久化 issuance 身份、接收 session/thread、不可变简报内容与动作列表。
   每个动作固定 key、expected attempt、依据和稳定操作身份。
2. 收到这一次 turn/start 的确切响应后，追加
   (session, thread, turn) → issuance；禁止覆盖已有绑定。
3. 动态工具调用从其可信传输上下文定位原 turn，解析 key/reason 后选择该简报内
   的动作。验证当前 session/角色/Track，之后仍走既有精确恢复及权限入口。
4. 首次成功提交恢复时，由既有请求指纹固定理由及回执。业务幂等来自稳定动作
   身份，不来自每次会变化的 callId；同一动作不同理由重试明确冲突。
5. 原事件、attempt、简报、调用及恢复回执保持可追溯。语义工具的回执只证明
   已接受/分配，不证明 Worker 已开工。

### F2-B 的具体存储与接线契约

基线更新至 `98071d18`。F2-A 已由 #1571 合入。F2-B 增加独立迁移，
不修改 0100 或其他已发布迁移；不更改已有 harness 快照字段的含义。

初始使用以下职责明确的持久化记录（实现可将动作放入有严格类型校验的 issuance
JSON，减少表数，但必须维持相同身份和不可变规则）：

| 记录 | 必须保留的内容 | 唯一性与含义 |
| --- | --- | --- |
| thread registration | Provider thread、所属 Planner card/Track、注册时间 | 只记录实际注册新语义工具的线程；旧线程不能因升级自动获得标记 |
| issuance | id、接收 session/thread/Track、实际发送内容、类型化恢复动作、创建时间 | 一个 id 对应一份不可变内容；动作含 key、原 attempt、依据事件、稳定恢复请求 key、当时可用性 |
| turn binding | session/thread/turn、issuance id、确认时间 | 同一 Provider thread/turn 只能绑定一次；同值重放成功，不同 issuance 或 session 明确拒绝 |
| call provenance | 原 session/thread/turn/callId、tool、规范参数指纹、首次接收时间 | 同一 callId 在原 turn 内不可改参数；只证明收到调用，不证明恢复成功 |

记录随 Track 一起删除；不随一次 Worker/Planner session 退出或展示快照清理而消失。
Track 外键级联清理，issuance 到 turn/call 的引用关系必须一致；不依赖事件行或会话行
永久存在。session/thread 身份保存为原始事实，执行调用时仍检查当前认证归属及
既有角色守卫。数据库唯一约束与写入口共同拒绝覆盖，不用 UPDATE 把旧绑定改到新执行。
旧数据库迁移后这些记录为空，不能给历史 turn 回填猜测的绑定。

发送顺序：

1. 简报构造一次返回展示段与类型化动作。只有内核可确定的原执行进入动作；来源是
   原始事件和数据库事实，不解析展示文字。动作不可凭 Worker 参数生成。
2. 本次输入与模型选择准备好后，在 turn/start 前提交 immutable issuance。
   固定实际将发送的内容和动作，在内核生成并保存稳定恢复请求 key。
3. 发送该内容。拿到该次请求的确切响应 turnId 后提交 turn binding。
   只有完成绑定才可以执行对应语义恢复。工具比绑定更早到达时，最多等待两秒；
   每次等待都不持有数据库事务、harness issuance 或 daemon 锁。
4. 绑定成功后，原有 harness 状态/展示快照照常保存。即使之后展示保存失败，
   已持久化的 turn binding 仍是精确事实，不会因重新准备输入而改绑。

首次版本不尝试跨失败发送复用 issuance：重新准备的输入可能已包含新事实，
因此每次重发生成新 issuance，旧的未确认 issuance 保留但不能被调用。
ACK 丢失不能通过 turn/started 通知、active turn 或“最后一条记录”补绑定。
绑定提交失败时返回明确的准备失败，保留输入并按既有有界退避恢复；未知旧 turn
的调用仍无副作用。此处不承诺消除既有不确定发送导致的重复模型轮次，但必须
保证它们不能通过改绑、重试或响应丢失造成重复业务恢复。

动态请求按 Provider 外层 threadId/turnId 定位持久化 binding，解析严格的
key/reason 参数，拒绝额外身份字段、未知工具和不支持 namespace。从 binding
得到原 session/Track/attempt，再检查当前 Planner 归属、该简报动作和当时的可用性。
当时不可用的动作返回具体前提，不因调用发生得更晚而悄悄变成另一个授权选项。
之后调用现有 recover_failed_task，所有实时权限、合同、停止证明与精确 attempt
比较继续由内核处理。

call provenance 可在恢复之前单独持久化，以便识别同一 callId 的变参重试；
它不是业务成功或“理由已被接受”的记录。崩溃后允许相同调用继续进入现有幂等
恢复入口，不根据“call 行已经存在”跳过恢复。不同 callId 但相同动作/理由仍复用
同一个恢复请求 key；首次成功的原子恢复事务固定理由和回执。

共享 daemon 通过明确的初始化依赖获得 repo/events/WriteContext，在每个新连接
安装独立消费者，不持有自身客户端强引用造成生命周期循环。最多并行处理 16 个
请求，复用 F2-A 的连接取消/响应期限；不阻塞 reader 和绑定 ACK 的提交。
只对新创建的、已有恢复处理器的共享 Planner thread 注册语义工具。普通 Worker、
Assistant 和旧 thread 不追加工具。客户端连接重建要恢复消费者；线程是否已注册
工具不能靠提示词猜测。旧 thread 继续使用精确 MCP；新 thread 若无绑定明确报错。

表结构、入参长度/动作数量/输入大小使用明确上限；第一版记录仅在需要恢复简报
绑定的 turn 上创建，避免每轮无条件写入。无限故障下的历史保留与清理仍受 Track
生命周期管理，不添加独立 GC 服务。新迁移须验证空库及已有快照/attempt 的升级，
全量扫清新字段、测试和生成物调用方。

确定性超限不能把已接受的对话输入永久卡在重试队列里。若本批输入超过简报存储
上限、动作过多或同 key 有多个执行无法唯一选择，保留全部原始事实与用户输入，
显式改用现有精确接口的简报展示，不创建本批语义动作绑定。必须在类型化构造阶段
重新渲染说明，不能留下“本轮可调用 Recover”的矛盾指令，也不能挑选最新执行、
静默删掉消息或放宽存储上限。真正的数据库/完整性故障仍走有界重试错误路径。

初次失败且尚待停止/settlement 时可以等待首份简报；已消费过简报后，用户在后续
turn 再决定恢复，不应等待不存在的新事件。没有本轮绑定时，明确保留读取精确证据
后使用旧 MCP 的路径，不给新 turn 隐式继承原简报权限。第一版语义操作只覆盖具有
唯一、本轮已确认动作的简报。

## 竞态、错误和重启

- 工具调用早于 turn 绑定提交时，可在独立处理任务中有界等待；超时返回
  not_ready，无副作用。等待不得持有发送或 issuance 所需锁。
- turn/start ACK 丢失、绑定提交失败或未知 turn：不猜 active/latest，不执行。
  调用方收到明确问题；恢复队列必须保留原意图和证据。
- 仅重发同一份不可变简报时，多个已确认 turn 可指向同一 issuance，复用动作身份；
  刷新事实产生新 issuance。重启不能把新 turn 冒充先前未知的 turn。
- 接受恢复后响应丢失：同一动作重试返回原回执。权限仍按既有入口认证，
  会话被替换的旧请求不能绕过认证；新会话如何查看既有回执须明确处理。
- User 先恢复、声明/合同变化、原执行被替换或授权撤回：原绑定不变，内核拒绝
  新副作用；把具体冲突交还 Planner。失败候选与重试次数规则不变。

## 验证及完成条件

确定性测试经真实传输、harness、持久化和恢复入口，包含正常、迟到、重放、权限
及故障分支。关键身份隔离/幂等断言做有预测的生产 mutation。每个 PR 两路独立
完整审查收敛，所需 gates 与 CI 通过后合入，禁止共享主机真实 Tier2。

F2-B 的真实产品演练必须观察到：Planner 收到恢复简报后直接调用仅含 key/reason
的语义工具，系统操作原 attempt、返回真实回执、最多一个 successor；权限耗尽时
明确停止。原生精确 REST/MCP 接口保留；旧会话没有新绑定时明确走旧接口或拒绝，
不悄悄制造语义工具能力。对首次通知早于完整简报的情形单独记录，不宣称零读取。
