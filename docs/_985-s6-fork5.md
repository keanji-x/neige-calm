# #985 切片 6 岔口 5：子 wave 终结后的父任务闭合

> 只读定向调研；未运行 `cargo build/test`。不重复 `_985-s6-survey.md` / `_985-s6-forks.md` 已裁定的创建、反链、输入与树预算。

## 1. wave 终结的既有语义

1. `WaveLifecycle` 共九态：`Draft/Planning/Dispatching/Working/Blocked/Reviewing/Done/Canceled/Failed`；定义及语义在 `crates/calm-types/src/model.rs:291-316`，终态仅后三者，`is_terminal` 在 `crates/calm-types/src/model.rs:318-327`。
2. 状态机真源是 `validate_transition`：同态幂等、非终态可由 user cancel、终态仅 user 可 reopen 到 Planning，happy-path/失败边见 `crates/calm-types/src/wave_lifecycle.rs:182-307`；完整权限表也写在 `crates/calm-types/src/wave_lifecycle.rs:28-45`。事务 helper 先校验、再更新并成对产出 lifecycle/update 事件，见 `crates/calm-server/src/wave_lifecycle.rs:47-81`、`crates/calm-server/src/wave_lifecycle.rs:90-128`；REST PATCH 同样先校验并在同事务发两事件，见 `crates/calm-server/src/routes/waves.rs:1172-1202`、`crates/calm-server/src/routes/waves.rs:1246-1283`。
3. 严格的生命周期事件只有 `Event::WaveLifecycleChanged{id,cove_id,from,to,...}`；行更新伴随 `WaveUpdated`，实体消失用 `WaveDeleted`，三者定义在 `crates/calm-types/src/event.rs:456-487`，kind tag 在 `crates/calm-types/src/event.rs:1398-1405`。
4. 现成挂点是持久事件 + 进程内 EventBus：事件先随写事务落库、commit 后广播，见 `crates/calm-truth/src/db/sqlite/events.rs:338-384`、`crates/calm-truth/src/db/sqlite/events.rs:416-424`。dispatcher 已订阅 `wave.deleted/lifecycle_changed/updated`，见 `crates/calm-server/src/dispatcher/mod.rs:743-782`；但 lifecycle arm 只 `poke(id)`，完全不看 `to`、不反查父 task，见 `crates/calm-server/src/dispatcher/mod.rs:1010-1024`。所以“可挂”但今天“未挂”。
5. 既有跨实体闭合先例有两套，且都是 live + sweep 共用 guarded reconcile：terminal 的 attach-reader 在持久 exit 后调用 `TerminalTaskHook`，见 `crates/calm-server/src/terminal_renderer/attach_reader.rs:90-114`；hook 解析 terminal→card→task，见 `crates/calm-server/src/scheduler/mod.rs:1942-2003`，再与 sweep 共用 `complete_terminal_task`，见 `crates/calm-server/src/scheduler/mod.rs:2025-2058`。agent worker 死亡也由 reaper 反查 op idem 后 guarded 写 task failed + 事件，见 `crates/calm-server/src/reaper/mod.rs:528-579`。

## 2. task 终结的既有链路

6. spawn op 成功后 `reconcile_spawn_result` 取 result card id，调用 `mark_running` 做 guarded `dispatched→running`，见 `crates/calm-server/src/scheduler/mod.rs:991-1038`；底层同时 COALESCE stamp card 和 deadline，且只匹配 dispatched，见 `crates/calm-truth/src/db/sqlite/task.rs:275-302`。
7. agent worker 通过 MCP `task_complete` / `task_fail` 产出 `TaskCompleted` / `TaskFailed`，见 `crates/calm-server/src/mcp_server/tools/emit.rs:157-186`、`crates/calm-server/src/mcp_server/tools/emit.rs:376-403`。`CardDecisionSink::commit_worker_task_report` 在同一个 eventized tx 内做 ownership guard、写 tasks 行并持久该报告事件，见 `crates/calm-server/src/decision_sink.rs:52-123`、`crates/calm-server/src/decision_sink.rs:141-190`、`crates/calm-server/src/decision_sink.rs:251-273`。
8. 成功 gate 在 DB 写环节分流：无 gate 的 `dispatched/running→done`，有 gate 的同源状态转 `verifying`；两个 UPDATE 及统一入口在 `crates/calm-truth/src/db/sqlite/task.rs:417-541`。失败不跑 gate，直接 `dispatched/running→failed`，见 `crates/calm-truth/src/db/sqlite/task.rs:609-650`。两边都有 wave_id、worker ownership、状态 guard，因而可安全重试。
9. `verifying` 的写者是上述成功报告事务；消费者是 dispatcher 收到 task event 后 poke scheduler，见 `crates/calm-server/src/dispatcher/mod.rs:975-1005`，`schedule_pass` 找 verifying 行并 `drive_gate`，见 `crates/calm-server/src/scheduler/mod.rs:552-570`。`drive_gate` submit/wait `task-verify` 并 reconcile，见 `crates/calm-server/src/scheduler/mod.rs:1701-1786`；gate result guarded `verifying→done|failed` 且同事务写 `TaskGateResult`/lifecycle 事件，见 `crates/calm-truth/src/db/sqlite/task.rs:569-607`、`crates/calm-server/src/operation/task_verify_adapter.rs:169-245`。
10. gate 的 cwd 确实按 `gate.cwd → task.cwd → tasks.wave_id 对应 waves.cwd` 冻结，见 `crates/calm-server/src/operation/task_verify_adapter.rs:652-705`，命令以该 cwd 启动，见 `crates/calm-server/src/operation/task_verify_adapter.rs:783-804`。判断：sub-wave 父 task **应尊重显式 gate**；child `Done` 是 agent/review 判断（状态语义见 `crates/calm-types/src/model.rs:307-315`），父 gate 是另一个机器验收合同，且已裁定 child 初始继承 parent workspace，见 `docs/_985-s6-forks.md:53-57`，故语义合理。实现应让 child Done 复用 `task_report_success_from_worker_tx(TaskReporter::Kernel)`：有 gate 进 verifying，无 gate done；若将来允许 child 脱离 parent/task cwd，必须另行改 gate cwd 合同，不能静默沿用本结论。
11. child `Failed` 应把父 task 写 `failed(child-wave-failed)`；child `Canceled` 也应写 `failed(child-wave-canceled)`，而不是 canceled：现有 canceled 只允许 `pending→canceled`，见 `crates/calm-truth/src/db/sqlite/task.rs:158-171`，in-flight cancel 明确拒绝，见 `crates/calm-server/src/mcp_server/tools/plan.rs:574-606`。child Done 的 TaskCompleted、其余 TaskFailed 都应与父行 flip 同事务，沿既有 worker/terminal 形状，见 `crates/calm-server/src/decision_sink.rs:111-190`、`crates/calm-server/src/scheduler/mod.rs:2058-2137`。

## 3. sweep 与崩溃安全

12. `sweep_reconcile` 先扫 `tasks_nonterminal`，Pending 收集 wave、Dispatched re-drive spawn、Running Terminal 查持久 exit、带 liveness deadline 的 Running 超时失败、其余 Running no-op、Verifying re-drive gate，见 `crates/calm-server/src/scheduler/mod.rs:1240-1313`。现成可照抄的外部状态 arm 是 `reconcile_running_terminal`：恢复 card id、读 terminal、仅在有 exit 时调用共享 completion tx，见 `crates/calm-server/src/scheduler/mod.rs:1634-1698`。
13. 只挂事件会失活：EventBus 是 bounded broadcast，发送时没有订阅者也静默成功，见 `crates/calm-truth/src/event_bus.rs:108-129`；dispatcher lag 明说丢事件并立即调 sweep，见 `crates/calm-server/src/dispatcher/mod.rs:806-830`。重启不会让这个内部订阅 replay 历史；可靠性来自 boot sweep 和周期 sweep，见 `crates/calm-server/src/scheduler/mod.rs:1183-1200`、`crates/calm-server/src/dispatcher/mod.rs:838-857`。
14. 因此新增一个共享 `reconcile_child_wave_task`：live 端由 terminal `WaveLifecycleChanged` 和 `WaveDeleted` 触发；sweep 端枚举所有 `status IN (dispatched,running)` 且 `child_wave_id IS NOT NULL` 的父 task，读 child 当前 row 后再判 `Done→success/gate`、`Failed→failed`、`Canceled→failed`、row missing→failed(deleted)，非终态 no-op。所有 UPDATE 都须带 parent task status + child_wave_id guard；事件只负责低延迟，DB 当前态才是裁决真源。guard + shared live/sweep 的依据是 terminal precedent `crates/calm-server/src/scheduler/mod.rs:1634-1698`、`crates/calm-server/src/scheduler/mod.rs:2025-2034`。
15. `tasks_nonterminal` 的集合正好覆盖 pending/dispatched/running/verifying，见 `crates/calm-truth/src/db/sqlite/read.rs:422-431`，可作 sweep 的全集；但当前 `TASK_COLUMNS/Task` 没有 `child_wave_id`，见 `crates/calm-truth/src/db/sqlite/task.rs:16-23`、`crates/calm-truth/src/model.rs:383-410`。为保持前片裁定的 targeted 列，宜新增窄 reader，而非扩公共 Task。sweep 本已全局扫描，正确性不要求新索引；live 端要按 child id 反查，宜加 `UNIQUE INDEX tasks(child_wave_id) WHERE child_wave_id IS NOT NULL`，同时固定“一 child 只属一 parent task”。现有索引以 wave_id 开头，见 `crates/calm-truth/migrations/0058_tasks_kind_claude.sql:49-54`，不能承担该反查。

## 4. 删除、归档与结构 FK

16. archive 不是终态而是正交可见性字段，见 `crates/calm-types/src/model.rs:275-279`；归档不应闭合父 task。DELETE handler 先停 harness/清 terminal，事务内删 overlay/lease、调用 `wave_delete_tx`，最后只发一条目标 wave 的 `WaveDeleted`，见 `crates/calm-server/src/routes/waves.rs:1324-1348`、`crates/calm-server/src/routes/waves.rs:1370-1432`。
17. `wave_delete_tx` 显式删 VCS、task_ref、该 wave tasks、worker_sessions，再删 wave；cards 由 wave FK cascade，见 `crates/calm-truth/src/db/sqlite/wave.rs:205-252`、`crates/calm-truth/migrations/0001_init.sql:31-40`。它不可能自动改另一 wave 的父 task。因此父 `child_wave_id` 指向 missing child 时必须 fail-closed 为 `failed(child-wave-deleted)` 并发 TaskFailed；清 NULL 会把“从未建成”和“建成后被删”混为一谈。
18. `tasks.worker_card_id` 今天是裸 TEXT，不是 FK，见 `crates/calm-truth/migrations/0058_tasks_kind_claude.sql:18-24`；`tasks.wave_id` 也刻意无 FK、删除时显式清，见 `crates/calm-truth/src/db/sqlite/wave.rs:218-230`。但 `parent_wave_id` 是树结构真源，建议做自 FK `TEXT NULL REFERENCES waves(id)`（默认 NO ACTION），而非裸列：parent 必须存在，单删有 child 的 parent 应在 handler 内先查并返回 Conflict，不能留下孤儿。
19. 不建议 `ON DELETE CASCADE`：现有单-wave handler只枚举目标 wave 的 cards/terminals，且 terminal→card 是 RESTRICT，见 `crates/calm-server/src/routes/waves.rs:1324-1342`；worker_sessions→wave 也无 cascade并需手删，见 `crates/calm-truth/migrations/0045_worker_sessions.sql:1-7`、`crates/calm-truth/src/db/sqlite/wave.rs:231-241`。数据库 FK cascade 会漏掉 descendant 的进程 teardown、无逐 child `WaveDeleted`，甚至被 RESTRICT 中止。显式“整棵树 leaf-first teardown + 每 child 事件”可后推；本片安全语义应是有 descendants 就拒删 parent。cove 删除已有“先枚举所有 waves/terminals，再删 cove cascade”的完整子树先例，见 `crates/calm-server/src/routes/coves.rs:317-351`、`crates/calm-server/src/routes/coves.rs:357-388`。

**推荐：父任务终结路径 = `WaveLifecycleChanged/WaveDeleted` live fast-path + `tasks` 非终态 sweep 共用一个 guarded `reconcile_child_wave_task`；child Done 复用 success→done/verifying，Failed/Canceled/Deleted 统一 fail，因为事件广播会丢而当前 DB 状态可重建，且该形状已被 terminal live+sweep 先例证明。**

**本片最小可自洽范围是 child 终态/删除映射、父行+TaskCompleted/TaskFailed 原子 flip、显式 gate 分流、live 订阅、boot/periodic sweep、`child_wave_id` 唯一索引与 `parent_wave_id` NO ACTION FK/父删拒绝，可以往后推的是递归 leaf-first 子树删除、逐 child 删除事件和 UI 删除交互。**
