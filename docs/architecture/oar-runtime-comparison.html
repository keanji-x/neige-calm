模块边界与依赖方向

箭头从依赖方指向被依赖方。框表示源码职责模块，外框表示归属；不表示进程、请求流或执行次序。

橙色：产品集成　绿色：实现机制　蓝色：公共契约
稳定边界：公共契约

AgentRuntime、Session 与能力 trait 由同一契约层定义；产品会话策略依赖该契约，不按 Codex / Claude 名称分支。

依赖禁止反转

公共契约不导入实现或宿主队列/权限类型。server 集成保留原数据库与产品 owner；其下 provider 协议不反向导入 server。

产品持久性仍由内核拥有

SessionController 复用现有 backend 控制路径；持久队列、幂等、审批和回执事务保留在原 owner。

领域概念与数量关系

关系线表示关联；端点基数说明数量。下图是目标概念模型，不是数据库表设计。

1：一个　0..1：可无　0..*：零到多个　1..*：至少一个
关联不是同一性

一批输入可合并投递；一次 steer 可进入已有 Turn。投递未知时与 Turn 的关联可为空，不能从一次请求构造“已经执行”的事实。

运行与权限

一条 Conversation 可有多次 WorkerSession。先后恢复可以创建多个 ControllerInstance；同一卡任一时刻只允许当前授权实例生效。

原生绑定

WorkerSession 的绑定在准备阶段可为空。Controller 可先构造；安装后首次发轮按原路径建立或加载绑定；原生 ID 还必须带 provider 与存储范围，不能充当权限证明。

输入版本

数量关系按完整历史计数。一条输入能经历多个条目修订与投递尝试；本次投递固定内容及实际存在的身份/版本；LegacyUser 可无身份、无版本，不补造地址。

接口与实现：工厂、统一句柄、控制对象

AgentRuntime 是工厂接口，Session 是对外句柄契约；SessionController 是该契约的实现。创建关系不是继承关系；工厂返回逻辑控制句柄，不要求先有原生 ready。

虚线空心三角：实现接口　虚线箭头：依赖 / 创建　实心菱形：组合拥有
统一入口

上游持有 AgentRuntime 接口，通过 open / resume 获得 Session。具体 provider 在组合根注册；公共调用路径不枚举厂商。

一个协调 owner

既有 backend 拥有协议状态，兼容 Codex 共享 app-server 与 Claude/ACP session。Controller/能力视图引用原对象，harness 拥有产品调度状态。

创建不意味着启动新进程

工厂可以复用共享 app-server，或接入已准入的执行上下文；进程终止权仍由相应资源 owner 管理。

能力组合：必需接口与可选接口

关联线表示对外暴露的能力视图。0..1 表示该绑定可以不提供此能力；不是每个 trait 各自创建一个 Session。

Session → CapabilityViews → controller-bound trait handles
所有能力共享一个控制 owner；存在 Compact 能力，并不意味着当前轮次允许压缩，更不意味着调用者已获授权。
能力不重复登记

支持与否来自实际组装结果；未协商的 PendingActivation 不冒充 Unsupported。供 HTTP / UI 使用的能力描述从同一来源导出，不另维护可能漂移的 supports_xxx 清单。

操作结果保留不确定性

TurnStartOutcome / SteerOutcome / CompactSubmission 等是唯一公共结果。四态仅在有具名显示消费者时由宿主派生，默认不实现；HostStopOutcome 留宿主，各 backend 恢复政策仍归原 owner。

业务队列不作为 provider 能力

产品持久排队已经由内核拥有；不为了统一方法名增加 Queue trait。未来使用原生队列时单独定义所有权转移契约。

OAR：通用 SDK 的现成参考

中立 API、发现与管理、原生记录和多后端覆盖更系统。产品持久化、审批和结算需要宿主另建，不能直接取代 Neige 内核。

本地：产品控制面的现有基础

持久队列、权限接管、历史控制和任务交付已有实现。欠缺的是中立接口与部分通用能力，不能把这些缺口都归因于原生 agent 不支持。

提案：可取的收敛方向，尚不完整

设计稿已规定发现管理、回应、观察和资源的归属。R1 保持现有行为，R2 单独扩展；本轮两路 Codex 评审，未宣称已实现。

契约内

中立请求、不透明相关性、具体操作结果与原生证据。公共请求不携带队列修订、Legacy 分支、Prepared 授权范围或宿主停止结果。

宿主侧

持久输入、旧格式兼容、PreparedInvocation、HostStopOutcome 与恢复政策继续由原 owner 管理；无具名显示消费者则不实现四态派生。

迁移取舍

M2 先 Codex；M3 用 ACP、Claude 检验不同语义。收益以跨边界依赖/重复机制消除证明，不编造流量或分支基线。
