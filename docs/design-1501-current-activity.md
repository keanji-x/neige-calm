# F3：当前执行的活动证据

状态：实施范围，尚未验收。基线 `9b91d077`。承接
[Planner 功能实施计划](design-1501-planner-contract-roadmap.md)的 F3，关联 #1501、#1492。

## 一个闭环

隔离 Codex Worker 执行一条长命令 → 用户询问进度 → Planner 通过已有
`calm.plan.list` 得到当前 attempt 的活动证据，解释等待或明确阻碍 → 命令结束、
任务产生后续事实。先解决一次进度判断，沿用现有完成通知，不增加定时模型唤醒。

`running` 只表示内核记录的任务阶段。命令调用记录、命令结束记录、任务报告、
验收结果和执行停止证明分别表达，任何一项都不能代替其他事实。

## 最小实现

在 plan.list 已有一致性事务内，通过当前 attempt 的 Operation receipt 定位其
Worker card 和 session，只读取该绑定的已有 worker-flow 记录。隔离执行已经
通过 WorkerSessionStarted 和私有 rollout 接入同一采集器，无需新日志管线。

返回有界近况及证据引用，明确区分 Provider 的发生时间、内核采集时间和查询
时间。历史补录的采集时间不能当作新的业务进展。未配对调用只能称为“观察到
调用，尚未观察到完成”，不能声称该命令此刻仍在执行。

采集器目前没有持久化的健康状态，因此健康保持未知。空记录、未知内容、
缺少绑定和历史截断必须可识别。沉默不改变任务状态、不证明卡死、不增加恢复
权限。普通工具返回成功也不能冒充命令 exit code 或业务验收。

复用现有 Planner 进度指导和精确过程/结果入口；不添加工具、迁移、权限、
后台监督器或 Terminal 操作。首版只保证隔离 Codex，其他路线明确说明覆盖范围。

## 验收

- 通过实际 plan.list 入口验证调用记录、明确结束、空/未知/截断证据。
- 替换 attempt、同卡其他 session 和跨 Track 数据不得混入当前摘要。
- 旧发生时间与新采集时间保持分离；缺少活动不能改变恢复资格或任务结果。
- 关键绑定断言经生产代码单因素 mutation；两路独立完整审查和适用 gates。
- 独立本地实例进行一次真实 Planner/Worker 长命令实验，记录实际读取和回答、
  源版本及限制。命令状态和任务结果分别核对，只清理本实例资源。
