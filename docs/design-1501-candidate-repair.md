# B: one rejected-candidate repair and renewed delivery

Status: approved implementation scope; behavior is not yet implemented. Baseline: 00851939d.
Related: #1501, A1 candidate verification, A2 candidate review, #1594 semantic dispatch.

## Outcome and scope

An internal Planner explicitly requests `calm.task.repair({producer, reason})` after an isolated candidate producer has completed, its declared machine checks passed, and its designated Reviewer completed with blocking findings and a successfully settled Operation. The kernel preserves C1 and the exact R1 report, creates one linked repair task and one new review task, and returns their stable keys and truthful admission state. No report revision, candidate hash, host path or manually copied review-event ID is a caller requirement.

First scope is one ordinary empty-workspace candidate producer with review-required policy, one designated Reviewer, one explicit repair round and one eventual consumer of C2. Machine-failed candidates, failed/missing review reports, recursive repair rounds, user-owned contract changes, arbitrary input sources, new Providers and a global Finding system are follow-ups. Existing authorization and User release/budget controls remain in force. Any stricter source eligibility must be explicit rather than silently falling back.

A repair is a new task with an immutable lineage to the original work, not a reset of its Done execution. Preserve the original producer and Reviewer tasks/attempts/reports. This avoids broadening Failed-only Recover and avoids invalidating C1's existing current-source authorization. The new review task gets a new identity; do not reuse a Done Reviewer or its old report. The new producer inherits the original goal, acceptance, output paths and machine checks; only mechanical wiring to the newly generated Reviewer changes. It must be described as a linked repair contract, never as byte-identical to the original context. Existing technical recovery, if admitted for these tasks, must retain the same exact repair inputs and does not authorize another repair round.

## Persistent decision and declaration authority

Use the existing Planner-only MCP/DecisionSink/report-writer path. Current persisted session/card/Track/area role and recorder permission are checked inside the transaction, including replay. Add only a new migration (0106 if still available), leaving <=0105 byte-frozen; update the maintained head-schema migration inventory.

A private immutable repair receipt binds the original source attempt and frozen contract, C1 publication/snapshot and successful verification, designated R1 authenticated report event/attempt/Operation and ordered blocking_findings, original Reviewer goal/acceptance, the derived repair/review declaration identities and contracts, and the request reason. A Track/source business identity allows only one repair round. Same request replays the same receipt; altered reason/contract conflicts. Replays never retarget a newer source or recreate edited/deleted repair declarations. Public responses must not serialize private storage paths or complete private operation payloads.

In the existing report transaction, append the two derived task blocks to the current CRDT, apply the normal declaration guard, project through the existing task allocator and publish the existing events together with the receipt. Both declarations and the receipt commit or roll back together; unrelated blocks survive. No direct tasks-row writer, separate scheduler, mutable accepted flag or new TaskAttemptOrigin is introduced. Do not add a generic batch editing platform merely to append these two blocks; a bounded internal purpose may apply existing block operations sequentially within this transaction.

Validate the original producer/Reviewer claim freezes before deriving contracts. Do not copy today's changed requirements as the original contract. Bind the exact observed failed review, not a free-text Planner rejection reason. The repair call itself is the explicit Planner choice; it does not require first pretending C1 was accepted. No old rejection lacking an authentic designated review can manufacture repair authority.

## Input and output binding

Keep the repair task's output an ordinary CandidateProducer so existing capture/verification/qualification/consumer paths own C2. Add a narrowly typed repair reference to the isolated execution selection if needed: optional for historical ordinary tasks, required and fully validated when repair is selected. A repair producer may use file-input only with its matching kernel receipt; the new Reviewer uses normal candidate-review input for C2 plus the same repair lineage. A copied or invented reference, different task key/Track, altered output policy, changed goal/acceptance or missing receipt must fail closed at claim and again at preparation/preturn. Readiness/User release remain admission controls rather than permission to alter the repair contract.

Reuse immutable candidate input binding and materialization with an explicit repair purpose. It permits C1 only for authorized repair, never normal consumption. Give the repairer exact C1 files at the existing `/workspace/inputs/source` location and instruct it to produce all declared repaired output files under `/workspace`; there is no extra transport task and no mutation of the sealed source. Include the original goal/acceptance and exact R1 findings in its kernel briefing. Store and revalidate the binding against the actual attempt and preparing Operation; technical retries must not select latest input.

After the repair worker stops, existing publication seals C2 and runs the inherited machine checks on C2. C1's checks cannot qualify C2 even when bytes match. The new designated Reviewer obtains C2 through the existing A2 binding, together with the original R1 problem list. Any source/contract withdrawal, missing/corrupt snapshot or invalid lineage prevents launch/qualification; do not silently skip a check.

## Re-review and acceptance

Preserve ordinary A2's two-field report shape. A repair re-review has a distinct required report shape: passed, blocking_findings, and finding_responses. Each response identifies the original finding's zero-based index and gives resolved/unresolved plus nonempty evidence. The original report event and candidate identities are kernel-bound, not model-supplied. Require exactly the full original index set, with no duplicate/out-of-range/missing responses. No waiver/ignore disposition in this slice. Passing additionally requires every original finding resolved and no new blocking findings. Nonempty evidence is a completeness constraint, not a machine proof of semantic correctness.

Enforce the conditional report schema both at authenticated report admission and when reading qualification evidence, so old two-field reports cannot bypass it. Tie full resolution evidence to the exact report event; preserving existing ordinary ReviewEvidence serialization is preferred to changing historical acceptance receipts. Any projection of the base passed/blocking fields must still revalidate the required repair evidence when accepting and consuming C2.

New review completion and Operation settlement remain distinct. Only fresh C2 machine checks, its designated authenticated complete re-review, successful review settlement and the existing explicit Planner acceptance can qualify C2. Accepting the review report is not accepting the repaired implementation. Old R1 notifications and old C1 decisions cannot release C2. A consumer explicitly references the returned repair producer; pre-existing consumers of C1 are never silently redirected. Report/plan reads and Planner briefings expose the lineage, outstanding findings and exact current stage without building a new activity platform.

## Acceptance and development gates

- Real report/MCP entry: create C1 with passing machine checks and R1 with at least two blockers; C1 remains non-deliverable. Repair creates only the linked producer/reviewer declarations and immutable receipt; duplicate/concurrent replay does not create another pair.
- Assert exact original goal/acceptance/files/checks and R1 event/order reach the repair worker, C1 stays byte-identical, and source changes/revocation/forged or cross-task references fail before launch. Exercise claimed/prepared/replay and supported technical recovery seams.
- Reject missing/duplicate/foreign indices, absent evidence, unresolved findings, new blockers, copied ordinary pass and mismatched/late reports. Demonstrate that accepting a review report or reusing C1 machine/verdict evidence cannot deliver C2.
- Produce changed C2 files, run fresh machine checks, re-review all original findings, explicitly accept, and deliver exactly C2 to one consumer. Preserve C1/R1 and both execution histories. Source version equality is checked in actual materialized copies.
- Minimal production-entry regressions, selected load-bearing mutation with predicted complete red set and byte restoration, two independent full-diff review channels with fresh review after fixes, appropriate quick Rust gates and real generators/fixture sweeps. Use the existing exclusive target-a2 cache and bounded concurrency; no local workspace-wide nextest.
- One bounded private native dialogue exercises the supported loop with synthetic harmless files; close owned processes afterwards. Do not touch 4140 or run shared-host real Tier2 E2E. PR CI must be green before authorized squash merge. Record context and follow-ups in #1501.
