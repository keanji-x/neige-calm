VERDICT: REVISE
[BLOCKER] §D2/D8 — `base_is_ancestor` is not necessarily a fact about the recorded candidate, and live/recovery paths can disagree — evidence: design:268 samples ancestry before staging/commit, while :270 recomputes against the retained ref; a surviving worker can reset the expected branch between those operations — fix: capture one post-commit OID and use it for ancestry, ref creation and output, with a live/recovery equality test.
[MAJOR] §D2/§11 B2-M10 — The replacement lease CHECK still admits invalid tuples through SQL NULL — evidence: read-only SQLite evaluation of design:315 returns NULL for both `(sha,NULL,NULL)` and `(sha,NULL,'A')`, which CHECK accepts — fix: make every valid branch NULL-safe and extend A2b to missing-source combinations.
[MAJOR] §D3/D7 — Delivery-time provenance checks do not enforce the promised exclusion of external checkouts from verification — evidence: after delivery, replace the lease path with a symlink to a clean external clone at the same candidate SHA; design:327/:514 check only HEAD and status, so both samples pass — fix: verify canonical path, repository identity and registration during gate sampling, or explicitly narrow D7 and register this gap.
[MAJOR] §D2/D8 — Failure state has no specified durable reader for the promised `code`, `reason` and `retry_allowed` — evidence: design:317 stores only settlement tag/event ID, :297 gives the derivation only delivery/candidate/abandonment/op, and precise classification depends on removable result files (:288) — fix: persist typed settlement details or explicitly load the exact settlement event by `settled_event_id` for both retry admission and views.
[MAJOR] §D4/§11 A2-M2 — The prescribed cancel-then-change-base recovery cannot restart that logical task — evidence: `crates/calm-truth/src/db/sqlite/task_projection.rs:1286` rejects canceled attempts, :1791 updates declarations only while pending, and `task_attempt.rs:208` permits recovery only from failed attempts — fix: prescribe editing the still-pending declaration directly, or cancellation followed by a distinctly named task.
[MAJOR] §D4 — The new unavailable/pending classifier is neither exhaustive nor consistent with delivery retry — evidence: design:291 makes `workspace_missing` nonretryable, but :369 still treats verifying attempts as Pending; conversely :367 declares failed attempts unavailable even when a pre-slice-4 gate failed while a retryable delivery remains — fix: classify outstanding/retryable delivery before task terminal status and explicitly classify exhausted delivery as unavailable.
[MAJOR] §D4 — `base:{attempt}` introduces unchecked dependency cycles — evidence: an existing pending attempt can reference itself, or A can base on B while B depends on A; `crates/calm-types/src/report_blocks/tasks.rs:696` builds the existing cycle graph solely from `depends_on` — fix: include unresolved base-attempt edges in cycle admission, covering self-reference and mixed-edge cycles.
[MAJOR] §5/§6 A28 — The slice-2 acceptance test requires functionality unavailable until slices 5 and 6 — evidence: design:546 invokes `base:{attempt}` and asserts `integrity.mismatches`, but :502 introduces base admission and :503 introduces integrity — fix: make slice 2 test ancestry using its available lease/delivery entry points, and place the declaration/integrity integration test after their dependencies.
[MINOR] §D4 — The declared wire shape is externally tagged, not internally tagged — evidence: design:355 specifies `{"attempt":"…"}` or `{"commit":"…"}` while requiring an internally tagged enum — fix: specify the matching Serde representation and exact-shape round-trip tests.
[MINOR] §D5/G9 — The replacement Planner recipe names an event as a callable tool — evidence: design:381/:588 prescribe `forge.pr.diff.read{…}`, whereas `plugins/git-forge/manifest.json:130` exposes `gh.pr.diff` with required arguments at :153 — fix: name the actual tool and separately describe its emitted event and caller-supplied SHA metadata.
[MINOR] §D2/D8 — `committed` overclaims changed content — evidence: design:303 concludes “tip contains new content” from unequal commit IDs, although a worker-created empty commit changes the OID without changing the tree — fix: describe OID change only, or record tree equality separately.
[MINOR] §2/§11 — Several citations violate the document’s stated path-expansion convention — evidence: design:3 says omitted prefixes mean `crates/calm-server/src/`, but cited `task_projection.rs` actually resides at `crates/calm-truth/src/db/sqlite/task_projection.rs` — fix: qualify these cross-crate citations consistently.
