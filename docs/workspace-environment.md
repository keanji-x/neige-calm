# Workspace 的项目执行环境

Neige 从 workspace 对应的项目目录加载开发环境，供 agent、终端任务和发布动作使用。用户不需要在每段对话里提醒 agent 使用 `direnv exec`。

## 配置

项目存在 `.envrc` 时，运行 Neige 的主机需要安装 direnv。用户通过自己的终端检查并授权配置：

```bash
cd <项目目录>
direnv allow
```

Neige 使用 direnv 自己的查找、父目录继承和授权规则，不会自动批准配置。配置未授权、执行失败、超时或输出无效时，受影响的执行明确失败，不会换用服务进程的 GitHub token 继续操作。没有 `.envrc` 的目录使用基础运行环境，无需安装 direnv。

项目凭据应放在该项目已有的环境配置中。某个交互式终端临时执行的 `export` 不会成为所有对话共享的项目环境。

## 隔离 worktree 和恢复

workspace 保留原项目目录和实际工作目录的关系。Neige 创建的 worktree 使用原项目的环境来源；对应子目录使用原项目中相应的目录。worktree 新建而原项目尚不存在的子目录使用该项目中最近的现有目录。显式指定的其他项目目录使用自己的环境。

任务释放 worktree 后，后续命令仍可从已记录的租约读取环境来源。这份历史关系只提供来源信息，不授予执行权限。

每个新执行实例重新加载环境。已经运行的进程保留启动时的环境；重新连接仍在运行的实例不会替换它的环境。Codex 已加载线程的 `resume` 也不会刷新环境，需要通过正常生命周期重新启动对应实例。

## 后端和凭据边界

- Codex 的命令环境按会话传递，共享 app-server 不接收项目的全局凭据。
- Claude 的模型请求与命令共用进程代理。Neige 保留模型连接的 HTTP/HTTPS 代理：优先使用服务设置，未设置时使用服务启动环境中的代理；项目 `.envrc` 对这些已选代理的覆盖和删除不会改变模型路由。项目的其他工具环境变量仍按项目配置加载。
- OpenCode 通过官方 shell 插件在命令执行前加载项目环境，保留原生配置选择的 shell、命令和实际工作目录。模型与原生控制进程只接收运营者环境；项目提供的任意模型 key、原生配置变量仍可供项目工具使用，不会因此替换模型进程的账号或权限配置。
- 不支持会话命令环境的 ACP 常驻后端按 provider、工作线和绑定目录隔离进程；一个项目的清理不会停止其他项目的实例。
- 独立进程和终端使用私密启动通道或已授权执行内部的环境加载器。Neige 的连接参数、后端登录配置和权限参数继续由各自的所有者管理。
- 项目搜索路径会保留，Neige 自己的命令目录放在前面。
- 发布动作通过私密通道传递完整项目工具环境；现有的 Git hook 凭据剥离规则继续生效。
- 终端任务和发布动作在准备与释放之间核对变量名集合；集合变化会拒绝该次释放，重新提交后使用新环境。

内核验收执行器使用它独立声明的受限环境。

Codex 使用完整的显式变量名列表替换线程原有过滤规则。SDK 的配置层会整体替换另一种过滤表示，因此项目变量名保留原始字符，不会因 Unicode 表键改写而丢失。若旧设置中的其他名字能匹配项目变量、却没有项目自己的同名值覆盖它，启动会明确失败，避免混入旧全局值。

环境值不会写入 Neige 的持久化执行规格、操作结果或配置诊断。使用 stdin 释放环境的入口保留既有的大小和变量名限制，超出限制时明确拒绝，不会截断。用户自己执行的命令如果输出凭据，命令输出仍可能进入终端记录。

OpenCode 的每个原生进程使用独立的插件就绪证明。Neige 在会话挂载、目录发现和提示提交前检查插件已经注册；插件未加载或已经清理时，受影响的操作明确失败。项目环境只通过私密管道传到 shell 创建钩子，不写密钥文件。原生进程重新启动后必须重新激活插件，旧进程的证明不可复用。

OpenCode 注册配置中的显式环境优先级只作用于模型与原生控制进程。shell 命令采用完整项目环境，包括项目自己的 HOME、XDG 目录、API key 和变量删除；Neige 只在加载后恢复内核运行参数和 OpenCode 固定的终端参数，并把内核命令目录放在项目 PATH 前面。项目环境代码本身看不到内核连接凭据。

运行期间主动修改 OpenCode 的原生插件配置后，应通过正常生命周期重新启动实例。上述检查覆盖 Neige 管理的进程与会话生命周期，不承诺将任意并发的原生配置热重载与工具执行原子绑定。该环境桥接覆盖 OpenCode 的本地 shell 命令，不自动改写 MCP 服务、格式化工具或其他原生子进程的环境。
