# #1727 S4 设计评审归档 — 第 1 轮，通道 codex（对 v1）

> 归档注：评审者原文，仅把 #1316 术语棘轮的退役词替换为「⟨退役词⟩」（0 处），其余逐字保留。评审对象：`docs/architecture/1727-s4-candidate-binding.md` v1，基线 `origin/main` @ `231845fd5`。当轮结论：REVISE 6B/13M/1m。处置见设计文档 §11 第 1 轮表。

VERDICT: REVISE
[BLOCKER] §D3 — The proposed pre-step mismatch observer cannot run because processless `task-verify` operations cannot enter Parked — evidence: `crates/calm-server/src/operation/mod.rs:891` requires spawn artifacts; `operation/driver.rs:631` compensates when they are absent — fix: specify a durable processless completion path, including restart recovery, without fabricating process artifacts.
[BLOCKER] §D1/D2 — Forge Operation results do not contain the proposed `{commit, branch, resolved_by}` receipt — evidence: `crates/calm-server/src/operation/forge_action_adapter/mod.rs:767` stores `{exit_code,event_kind,event}`, while `mcp_server/tools/emit.rs:342` extracts only branch/commit_sha — fix: define and persist the exact delivery-result contract, including recovery provenance, and sweep its producers and consumers.
[BLOCKER] §D2 — Reusing `submit_forge_action` loses the preallocated operation key on which reconciliation depends — evidence: `crates/calm-server/src/mcp_server/transport.rs:989` assigns `operation_key: new_id()`, whereas D2 joins Operations using the delivery row’s key — fix: share a submission function accepting the persisted OperationKey verbatim across emit and sweep.
[BLOCKER] §D2 — The lease CHECK contract makes every new `head` or `commit` base invalid — evidence: the table requires all three base columns simultaneously non-NULL but permits `base_attempt_id` only for `attempt` — fix: require base_sha/base_source together and require base_attempt_id exactly when base_source is attempt.
[BLOCKER] §D2 — Abandoning a failed delivery contradicts its immutable settlement transition — evidence: failure writes `settlement='failed'`, abandon writes `'abandoned'`, but the specified trigger permits only NULL→value — fix: preserve failure settlement and record abandonment as a separate durable decision, with an explicit effective-state derivation.
[BLOCKER] §D2/G4 — The `tip` fallback can certify a commit that was never the delivery’s result, not merely misidentify its author — evidence: construction: missing/torn result files, no delivery trailer, foreign clean C2 after the crash; the proposed probe mints C2 — fix: return unresolved unless durable execution evidence identifies the delivered commit.
[MAJOR] §D3/G1 — Clean HEAD/status samples do not establish that all steps executed against candidate bytes — evidence: construction: a tracked symlink targets a persistently modified external file; both samples remain clean without any restore, and G2 already excludes ignored inputs — fix: narrow the success claim to sampled Git observations and register external-input limitations, or introduce an enforceable verification boundary.
[MAJOR] §D1/D7 — The candidate’s actual repository/branch provenance is not established by the proposed checks — evidence: `crates/calm-types/src/forge_git.rs:10` echoes the supplied branch; construction: a worker changes branch or redirects the leased path to another clean checkout with the same HEAD — fix: validate repository identity, worktree registration, canonical cwd and branch, or label these fields as intended rather than observed.
[MAJOR] §D2/D9 — Successful commits can become permanently unpublishable without a durable failure or supported recovery action — evidence: construction: teardown deletes the branch before candidate-ref creation and the object becomes unavailable; D9 only retries update-ref while the Operation remains succeeded — fix: define retention through publication and an explicit publication-failure settlement/action.
[MAJOR] §D2 — Delivery retry lacks both exact failed-operation binding and a replay-first admission order — evidence: construction: retry R succeeds but its response is lost; replay now fails the “no candidate/latest failed” checks, while a stale request can target a newer failed delivery — fix: require the expected failed delivery ID and return fingerprint-checked request receipts before current-state admission.
[MAJOR] §D4/§5 — Adding base to the hash and declaration alone neither transports its frozen value to prepare nor completes the ordinary drift contract — evidence: `crates/calm-server/src/scheduler/mod.rs:210` builds payloads from frozen task rows; `crates/calm-truth/src/db/sqlite/task_projection.rs:26` has a separate drift field set; `task_context.rs:1402` pins its equality — fix: specify durable base storage, projection/claim/prepare transport and drift comparison.
[MAJOR] §D5 — Candidate-derived head_sha breaks existing review replay unless both classifiers are changed — evidence: `crates/calm-server/src/mcp_server/tools/review.rs:153` classifies before the transaction and `:409` compares the supplied head_sha; candidate_id is absent from equality — fix: normalize candidate evidence before both classifications, compare candidate identity, and preserve subject-level numbering/cap policy.
[MAJOR] §D5/D7 — “Code subjects require candidates” and “noncandidate PRs cannot merge” are not enforced — evidence: construction: submit a PR subject with neither optional field; D5 accepts it as design; `plugins/git-forge/main.rs:430` also permits merge without expected_head_sha — fix: define an explicit subject discriminator and the required merge consumer, or withdraw the kernel-enforced merge claim.
[MAJOR] §D6/D8 — Required candidate fields cannot represent the advertised pending/failed/abandoned states or rejection before candidate creation — evidence: D8 requires candidate_id/commit_sha/resolved_by before minting, and D6’s rejection receipt requires a candidate FK — fix: separate delivery from an optional minted candidate and define typed verification/decision variants with state-appropriate required fields.
[MAJOR] §5 — The slices lack a safe upgrade contract for executions crossing deployment boundaries — evidence: construction: slice 1 stamps base_sha, completion precedes slice 2, and slice 4 later waits for a delivery row never allocated; existing frozen gates also lack the new required target (`task_verify_adapter.rs:317`) — fix: define versioned binding eligibility and explicit handling of historical reports, frozen operations and already-completed unbound gates.
[MAJOR] §2.7 F7.1/§2.9 — Passing the lockstep scanner does not justify leaving a new event kind at version 20 — evidence: `crates/calm-truth/migrations/0100_task_execution_settled_event_version.sql:1` versions an additive kind; `fe/core/events/reducer.ts:56` advances past malformed events at an accepted version — fix: negotiate/version the new discriminator with a new stamping migration, separately from compatible optional fields.
[MAJOR] §2.7 F7.2/§5.1.8 — Catch-up does not automatically inherit a new push predicate — evidence: `crates/calm-server/src/harness/catch_up.rs:23` queries the explicit `PLANNER_CATCH_UP_KINDS`, which also determines live subscription (`dispatcher/mod.rs:82`) — fix: include that list, live handler routing and live/boot parity tests in slice 2.
[MAJOR] §D8/§5 — Adding candidate keys to runs views needs a projection invalidation mechanism, not just a reader change — evidence: `crates/calm-truth/src/track_fs_view/mod.rs:326` builds runs from cards/events; `track_vcs/delta.rs:442` ignores worktree bookkeeping, and candidate mint emits nothing — fix: specify row-backed loading plus a durable invalidation trigger and full/incremental projection equivalence tests.
[MAJOR] §6 A4/§5 — Two prescribed must-red tests do not distinguish their proposed mutations — evidence: `forge_action_adapter/mod.rs:1602` recovers authoritative result files before probing, so the pre-fence crash need not exercise the mutated probe; removing the failed-settlement guard still leaves the candidate-exists guard rejecting slice 3’s test — fix: target the missing-result crash window and isolate each guard with independently admissible fixtures.
[MINOR] §2.8 F8.4 — The claimed zero-hit prompt/template scan uses the wrong repository paths and is false as stated — evidence: `crates/calm-server/prompts/tools/calm.task.dispatch.md:1` contains `/tmp` — fix: scan the actual directories and narrow the claim to instructions recommending an external Git checkout.
