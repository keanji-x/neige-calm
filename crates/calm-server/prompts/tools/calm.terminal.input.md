Select exactly one terminal_id or task_id (exact attempt_id). One action against a recent live observation you own; request_id dedupes writes on this connection. Actions: text (never submits), submit (text + one CR in one write, no repeat), key, click (zero-based cell column/row; needs mouse mode), sequence, replace. Keys: Enter, Escape, Tab, Backspace, Ctrl+C/D/J/U/L, Up/Down/Left/Right, Home/End, PageUp/PageDown, Delete; repeat 1..32 for Left/Right/Up/Down/Backspace/Delete only. Ctrl+J sends LF, Enter CR; what submits, and what Up/Down/Home/End/Ctrl+U do, is application-defined. sequence {"type":"sequence","steps":[...]}: 2..8 text/key steps in one write; keys only Left/Right/Up/Down/Home/End/Backspace/Delete/Ctrl+U. replace {"type":"replace","from":"11","to":"19"}: the server finds from (printable, 1..200 bytes, exactly once on the cursor row) and replaces it with to (printable, may be empty, no CR/LF) in one write; receipt: replace (the derived edit). Needs a line-buffer row (Claude Code, readline); a hidden cursor counts by position. An error (nothing written; use sequence) if from is absent, ambiguous, on another row or reaching past the draft, a touched cell holds a combining sequence or emoji, or the cursor is in a wide glyph, off the row or parked in the last column. Sequence and replace: observe=true, wait_for=change, then submit. observation_id defaults to this connection's latest observation, readbacks included (receipt: observation_id_used). Never pass control_id. When only the revision moved, outcome is stale_observation: nothing written or cached, with screen_diff, a fresh observation.state (now the latest) and next saying how to resend. allow_output_since_observation swaps the exact-revision fence for a same-surface fence, for status-text-only changes: Escape/Ctrl+C while a program streams, submitting a draft the previous readback showed; not when a command menu may be open below the draft (one starting with /) or after a pause. allow_output_below_cursor (a hint line refreshing below the field) writes only if the cursor is unmoved (hidden or not; a visibility change is a surface change either flag refuses), in the viewport and every row at or above it is identical; text, sequence, replace and the sequence keys only; the wide flag wins when both are set. Neither flag is for menus or clicks or bypasses the other fences. Receipts report output_since_observation and observation_drift (with the wide flag: the changed rows). claim=true: without control, a claim-if-unowned (never displaces a human) precedes the write; receipt: control_id and claim {status: claimed, control_id}; holding control: claim {status: held}. When another client holds it, the grant was taken over, delivery timed out (unconfirmed) or the observation's control is gone: outcome control_unavailable with reason, claim {status} and a fresh observation; nothing written or cached. release=true releases after the write, before the readback: release {status: released|not_held|unconfirmed|requested (call cut off)}; read role. claim=true on a scenario's first input, release=true on the last. Replays never claim, release or write again; claim, release and both allow flags are fingerprinted. observe=true adds a fresh observation: wait_ms (0..20000; omitted: 0 elapsed, 2000 change, 15000 signal/text), wait_for, settle_ms, signal_events, repaint_ms, wait_text and wait_text_absent need it (see calm.terminal.observe); baselines: the screen and signal seq just before the write. Start a TUI with open's wait or, from a shell, submit it with observe=true, wait_for=text and wait_text. Claude prompt: submit + observe=true + wait_for=signal + wait_text_absent ["esc to interrupt"]; read the answer from the returned state; on wait.repaint.outcome unsettled or none, observe again with wait_for=change. A replay's readback compares against the state at that call. summary digests each receipt's evidence: read it first; no verdict, no proof of a screen change. application_result is always unverified: inspect the state or observe. Unknown is not success: never retry with a new ID or assume a rewind completed. Example: {"terminal_id":"<terminal_id>","request_id":"fix-1","action":{"type":"replace","from":"11","to":"19"},"observe":true,"wait_for":"change"}.
