Text never submits: send key Enter separately, or use {"type":"submit","text":"..."} which writes the text and one CR in a single physical write (one receipt; repeat is not allowed) for sending a prompt or command line in one action. Keys: Enter, Escape, Tab, Backspace, Ctrl+C/D/J/U/L, Up/Down/Left/Right, Home/End, PageUp/PageDown, Delete. Optional key repeat is an integer 1..32 (default 1); repeat>1 is allowed only for Left/Right/Up/Down/Backspace/Delete and sends one bounded action. Enter/Escape/Tab/Ctrl keys cannot repeat. Ctrl+J sends LF and Enter sends CR; application-specific newline/submission behavior must be verified. Click uses zero-based terminal cell column/row and requires application mouse mode. A bounded edit is one action: {"type":"sequence","steps":[...]} with 2..8 text or key steps is one physical write with one receipt (steps reports the count); keys allowed inside are Left, Right, Up, Down, Home, End, Backspace, Delete and Ctrl+U, so a sequence never carries Enter, Ctrl+J, Escape, Tab, other Ctrl keys, PageUp/PageDown, submit, click or a nested sequence; at most 16384 encoded bytes. What Up/Down/Home/End/Ctrl+U do is application-defined: inspect the draft. Omit observation_id to use the latest observation on this connection, action readbacks included (the receipt reports observation_id_used); pass it only after an image observation or to act deliberately on an older observation. Never pass control_id as an input argument. The observation must still match the live screen. When every other fence passes (binding, connection, observation age, control, availability, no pending write, live viewport, input surface) and only the revision moved, the call succeeds with outcome stale_observation instead of an error: nothing was written, nothing is cached under the request_id, and the result carries observed_revision, current_revision, screen_diff {compared,cursor {moved,visible},rows_changed_total,rows_changed_at_or_above_cursor,rows_changed_below_cursor} and a fresh observation.state registered as this connection's latest. Inspect it: if only rows below the cursor changed (cursor unmoved, rows_changed_at_or_above_cursor 0) resend the same request_id with allow_output_below_cursor=true; if only status text changed elsewhere resend with allow_output_since_observation=true; else act on the new state. allow_output_since_observation=true replaces the exact-revision fence with a same-surface fence: use it for Escape/Ctrl+C while a program streams and for typing or submitting in an input field whose surrounding status text keeps changing, after inspecting the fresh state; never for menu selection or clicks. allow_output_below_cursor=true is the narrower opt-in for an input field whose hint or status line below it refreshes (Claude Code's draft box): the write proceeds only when the cursor is visible, unmoved and inside the viewport and every row at or above it is identical in text and presentation; refused for click, never for menus (a completion menu opening below the cursor is not benign); allow_output_since_observation wins when both are set. Neither flag bypasses the control, surface, viewport or pending fences. The receipt then reports output_since_observation and observation_drift (with tolerance below_cursor, rows_changed_below_cursor (first 16), rows_changed_total and truncated when the tolerance admitted it). claim=true folds a claim into the first input of a scenario: when you observed as observer and hold no control, a claim-if-unowned (never displaces a human) precedes the write and the receipt carries control_id and claim {status: claimed, control_id}; when you already hold control it reports claim {status: held}. When another client controls the terminal, the claim was taken over, its delivery timed out (status unconfirmed) or your observation named a control you no longer hold, the call succeeds with outcome control_unavailable, reason, claim {status} and a fresh observation, nothing written or cached. A granted claim that then hits the stale fence still reports claim {status: claimed}. release=true releases control after the write, before the readback: the receipt carries release {status: released|not_held|unconfirmed} and the readback shows role observer; a release never rewrites the write outcome. Use claim=true on the first input of a scenario and release=true on its last. A replayed request_id never claims, releases or writes again; claim, release and both allow flags are part of the request fingerprint. Set observe=true to include a fresh text observation after this action; wait_ms (0..20000; omitted means 0 for elapsed, 2000 for change, 15000 for signal and text), wait_for=change (baseline is the screen just before the write; settle_ms 0..2000), wait_for=signal (baseline is the signal seq read just before the write, so a hook signal caused by this action is reported; signal_events optional; after the signal the readback waits for the screen to repaint and settle, see calm.terminal.observe repaint_ms/settle_ms) and wait_for=text with wait_text (returns once the live screen shows one of the patterns and settles; see calm.terminal.observe) require observe=true.
