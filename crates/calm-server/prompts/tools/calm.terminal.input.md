Select exactly one terminal_id or task_id (exact attempt_id). One action against a recent live observation you own; request_id dedupes writes on this connection. Actions: text (never submits), submit (text + one CR in one write, no repeat), key, click (zero-based cell column/row; needs mouse mode), sequence, replace. Keys: Enter, Escape, Tab, Backspace, Ctrl+C/D/J/U/L, Up/Down/Left/Right, Home/End, PageUp/PageDown, Delete; repeat 1..32 for Left/Right/Up/Down/Backspace/Delete only. Ctrl+J sends LF, Enter CR; what submits is application-defined. sequence {"type":"sequence","steps":[...]}: 2..8 text/key steps, one write; keys only Left/Right/Up/Down/Home/End/Backspace/Delete/Ctrl+U (what Up/Down/Home/End/Ctrl+U do is application-defined). replace {"type":"replace","from":"11","to":"19"}: the server finds from (printable, 1..200 bytes; exactly one occurrence on the cursor row) and writes Left/Right to its end, one Backspace per character and to (printable, may be empty, no CR/LF) in one write; receipt: replace {row,cursor_index,cursor_visible,moves {key,repeat}|null,erased,inserted} (a replay returns it). A hidden cursor is used by position (Claude Code hides it yet places it at the edit point). An error (nothing written; use sequence) if from is absent, ambiguous, on another row or reaching past the draft, a touched cell holds a combining sequence or emoji, or the cursor is in a wide glyph, off the row or parked in the last column. Assumes the cursor row is the line buffer (one character per cell, arrow key and Backspace: Claude Code, readline); a from on another row is refused; a wrapped draft's cursor row is edited as any row. Sequence and replace: observe=true, wait_for=change (the readback is the preview), then submit. observation_id defaults to this connection's latest observation, readbacks included (receipt: observation_id_used); pass it for an older one. Never pass control_id. When only the revision moved, outcome is stale_observation: nothing written or cached, with screen_diff (cursor moved/visible, changed rows at/above and below it) and a fresh observation.state (the latest). Resend the same request_id with observation_id omitted plus allow_output_below_cursor=true if only rows below an unmoved cursor changed and the action edits the draft, or allow_output_since_observation=true if only status text changed; else act on the new state. allow_output_since_observation swaps the exact-revision fence for a same-surface fence: use it for Escape/Ctrl+C while a program streams, and to submit a draft the previous readback already showed (Claude Code's status line below the input refreshes a second after typing and would refuse the Enter). Keep the plain fence when a command menu may be open below the draft (one starting with /) or after a pause; a stale result's screen_diff still says which flag applies. allow_output_below_cursor is narrower (a hint line refreshing below the field): writes only if the cursor is unmoved (hidden or not; a visibility change is a surface change), in the viewport and every row at or above it is identical; text, sequence, replace and the sequence keys only; allow_output_since_observation wins when both are set. Neither flag is for menus or clicks or bypasses the other fences. Receipts report output_since_observation and observation_drift; when the wide flag admitted a moved revision, the receipt lists the changed rows (indices and counts at/above and below the cursor). claim=true: without control a claim-if-unowned (never displaces a human) precedes the write; receipt: control_id and claim {status: claimed, control_id}; holding control: claim {status: held}; another client holds it, the grant was taken over, delivery timed out (unconfirmed) or the observation's control is gone: outcome control_unavailable with reason, claim {status} and a fresh observation, nothing written or cached (resend with claim=true once free; else wait or ask). release=true releases after the write, before the readback; release {status: released|not_held|unconfirmed|requested (call cut off)}; read role; replays never release or rewrite the write outcome. claim=true on a scenario's first input, release=true on the last. A replay never claims, releases or writes again; claim, release and the allow flags are fingerprinted. observe=true adds a fresh observation: wait_ms (0..20000; omitted: 0 elapsed, 2000 change, 15000 signal/text), wait_for, settle_ms, signal_events, repaint_ms, wait_text and wait_text_absent need it (modes: calm.terminal.observe); baselines: the screen and signal seq just before the write. Start a TUI with calm.terminal.open's wait (or from a shell: submit it with observe=true, wait_for=text and wait_text). Claude prompt: submit + observe=true + wait_for=signal + wait_text_absent ["esc to interrupt"]: returns once the busy hint is gone and the screen quiet; read the answer from the state (the tool cannot know it is one). wait.conditions.absent = hint gone on the last tested screen; wait.repaint.outcome = the quiet window: unsettled = budget ended before quiet-with-conditions (the hint may have just vanished), none = nothing repainted; observe again with wait_for=change either way. A replay's readback compares against the state at that call; a failed readback keeps the receipt. summary {action,readback,screen,settled,signal,repaint,matched,role,control_id,exited,claim,release} (nullable) digests each receipt's evidence: read it first; no verdict, no proof of a screen change. application_result is always unverified: inspect the state or observe. Unknown is not success: never retry with a new ID or assume a rewind completed. Full state in structuredContent; the text block is the summary in words.
