Select exactly one terminal_id or task_id (exact attempt_id). One action against a recent live observation you own; request_id dedupes writes on this connection. Actions: text (never submits), submit (text + one CR in one write, one receipt, no repeat), key, click (zero-based cell column/row; needs application mouse mode), sequence, replace. Keys: Enter, Escape, Tab, Backspace, Ctrl+C/D/J/U/L, Up/Down/Left/Right, Home/End, PageUp/PageDown, Delete; repeat 1..32 (default 1) for Left/Right/Up/Down/Backspace/Delete only, never Enter/Escape/Tab/Ctrl. Ctrl+J sends LF, Enter CR; what submits is application-specific. sequence {"type":"sequence","steps":[...]}: 2..8 text/key steps in one write (receipt steps reports the count), keys only Left/Right/Up/Down/Home/End/Backspace/Delete/Ctrl+U (Up/Down/Home/End/Ctrl+U are application-defined); ≤16384 encoded bytes. replace {"type":"replace","from":"11","to":"19"}: the server finds from (printable, 1..200 bytes; exactly one cell-aligned occurrence on the cursor row) and writes Left/Right to its end, one Backspace per character and to (printable, may be empty; no CR/LF) in one write; receipt: replace {row,cursor_index,moves {key,repeat}|null,erased,inserted} (a replay returns it). An error (nothing written; use sequence) if from is absent, ambiguous (overlaps count), on another row or cutting a cell, or the cursor is hidden, inside a wide glyph or off the row. Assumes the cursor row is the line buffer (one character per cell, arrow key and Backspace: Claude Code, readline); it cannot prove the text is an unsubmitted draft or edit a wrapped one. Sequence and replace: observe=true, wait_for=change (the readback is the preview), then submit. observation_id defaults to this connection's latest observation, readbacks included (receipt: observation_id_used); pass it after an image observation or to act on an older one. Never pass control_id. When only the revision moved, outcome is stale_observation: nothing written or cached, with observed_revision, current_revision, screen_diff (cursor moved/visible, changed rows at/above and below the cursor) and a fresh observation.state (now the latest). Resend the same request_id with observation_id omitted plus allow_output_below_cursor=true if only rows below an unmoved cursor changed (rows_changed_at_or_above_cursor 0) and the action edits the draft, allow_output_since_observation=true if only status text changed elsewhere; else act on the new state. allow_output_since_observation swaps the exact-revision fence for a same-surface fence (Escape/Ctrl+C while a program streams, typing while status text keeps changing). allow_output_below_cursor is narrower (a hint line refreshing below the field): writes only if the cursor is visible, unmoved, in the viewport and every row at or above it is identical in text and presentation; text, sequence, replace and the sequence keys only (invalid params otherwise); allow_output_since_observation wins when both are set. Neither flag is for menus or clicks; neither bypasses the other fences. Receipts report output_since_observation and observation_drift (tolerance below_cursor when it admitted the write). claim=true: without control a claim-if-unowned (never displaces a human) precedes the write; receipt: control_id and claim {status: claimed, control_id}; holding control: claim {status: held}; another client holds it, the grant was taken over, delivery timed out (unconfirmed) or the observation's control is no longer yours: outcome control_unavailable with reason, claim {status} and a fresh observation, nothing written or cached (resend with claim=true once free, else wait for the human or ask before a deliberate control claim); a claim granted before a stale result is still reported. release=true releases after the write, before the readback; release {status: released (held before, none after, a takeover in between included)|not_held|unconfirmed (not sent or delivery timed out)|requested (the call was cut off)}; read role; replays return it unchanged and never release; the write outcome is never rewritten. claim=true on a scenario's first input, release=true on the last. A replayed request_id never claims, releases or writes again; claim, release and the allow flags are in the fingerprint. observe=true adds a fresh observation: wait_ms (0..20000; omitted: 0 elapsed, 2000 change, 15000 signal/text), wait_for, settle_ms, signal_events, repaint_ms and wait_text need it (modes: calm.terminal.observe); baselines are the screen and signal seq just before the write (a hook this action causes counts). Start a TUI with calm.terminal.open's wait, or from a shell: submit its command with observe=true, wait_for=text and wait_text naming the target screen (not the prompt). Claude prompt: submit + observe=true + wait_for=signal; repaint already|settled means the state shows the answer, none means observe once with wait_for=change, as when hooks_seen stays false. A replay's readback compares against the state at that later call; a failed readback keeps the receipt (observation unavailable). summary {action,readback,screen,settled,signal,repaint,matched,role,control_id,exited,claim,release} (nullable) digests each receipt's evidence (the readback's wait and control facts, the claim/release status): read it first; it is no verdict and no proof of a screen change. application_result is always unverified: inspect the state or observe. Unknown is not success: never retry with a new ID or assume a rewind completed. Full state in structuredContent; the text block is the summary as one line.
