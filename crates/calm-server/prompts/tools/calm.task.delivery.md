Planner-only: decide a failed Git delivery of an attached worker attempt — `action: "retry"` or `action: "abandon"`. Read the target from `calm.plan.list` (`detail: "full"`, the exact key): `expected_attempt_id` is the entry's current `attempt_id`, `expected_delivery_id` is `candidate.delivery.delivery_id`; both must be current or the call is refused (the refusal names the current id). `idempotency_key` is your request key: the same key with the same `action`, `expected_delivery_id` and `reason` replays the original receipt (safe after a lost response, whatever the state is now); the same key with different arguments is refused. Admission, after replay: the delivery must be the attempt's latest and its `candidate.delivery.state` must be `failed` — `pending` waits for `task.git_delivery_settled`, `committed` / `no_change` already has a candidate (accept it with `calm.task.verdict`), `abandoned` is final. `retry` requires `failure.retry_allowed` (read from the delivery row; `workspace_missing` never is) and the worker workspace still on disk; it inserts the next delivery (`ordinal + 1`, `predecessor_delivery_id` = this one) and runs the delivery script again, which settles into another `task.git_delivery_settled` (a candidate or another failure, each waking you once). A retry delivers the branch tip as it stands now; commits and files added after the base by anyone are included. `abandon` records that no candidate will come from this attempt: a gated task still `verifying` is flipped to `failed` (`status_detail: delivery-abandoned`), which releases its Track budget slot, and its `task.failed` does not wake you — this receipt is the answer; an ungated task stays `done` (`task_outcome: "done_unchanged"`); a gated task the gate already finished stays as it is (`task_outcome: "already_terminal"`). Result: `{delivery_id, ordinal, action, task_outcome, task_status}` — `delivery_id`/`ordinal` name the new delivery for a retry and the abandoned one for an abandon; `task_outcome` is `null` for a retry; `task_status` is the task row status observed by the call. Track lifecycle is not consulted (same rule as `calm.task.verdict`): the action is admitted on a Done Track too. `reason` is free-form and persisted with the decision.
