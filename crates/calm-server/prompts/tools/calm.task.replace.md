Planner-only: replace one codex or claude task of this attached Track with the next round of the same work, carrying its candidate onto the base a new task starts from. `key` and `expected_attempt_id` (the current attempt `calm.plan.list` shows) name the predecessor; `idempotency_key` makes the request replayable (the same request returns the same receipt with `replayed: true`; a different request under the same key conflicts); `reason` is recorded. `goal` and `acceptance` are required and are the complete contract of the next round; nothing is inherited from the predecessor's goal, acceptance or context. State what to change and how it is judged; never write a base commit, a diff to apply or a baseline to check — the kernel owns the base. `context` replaces the predecessor's context wholesale (default `{}`). The kernel stops a `running` predecessor as `calm.plan.cancel` would and cancels a `pending` one; a finished one stays as it is. The predecessor's block stays unchanged; the successor block, keyed `<root>.<n>` (`implement-x` → `implement-x.2` → `implement-x.3`), is appended right after it with the predecessor's `gate` and `no_gate_reason`, `kind`, `depends_on`, `priority` and `spawn`, `ready` and Planner-declared. `carry` (default `candidate`) takes the predecessor's settled candidate whatever its task status (a gate-red or rejected producer included), else the carry the predecessor itself received; `none` starts from that base alone. When the successor is prepared, the kernel merges that candidate onto the base a new task would start from then (the upstream, or the checkout's HEAD when HEAD is ahead of it or has none) and starts its worktree from the result; a conflict fails it as `spawn-failed: refused: carry-conflict: <paths>` (replace it again with `carry: "none"`, or declare a task that resolves the conflict), and a carry that cannot be computed fails as `spawn-failed: carry-infra`. `calm.plan.list` then shows `candidate.carry`; `no_change` on a carried attempt means nothing beyond the carry changed. Refused, with nothing written: a `dispatched` or `verifying` predecessor, a running one without a worker card, an unsettled delivery, an attempt already replaced, unfinished dependents, a child-Track route, an isolated or terminal-kind task, a declare-and-wait Track and an ended Track. Editing the successor off that route later fails its start as `spawn-failed: refused: replace-route-changed`. Returns `replayed`, `receipt_id`, `predecessor` {`key`, `attempt_id`, `prior_status`, `stop`: `canceled_now` | `already_terminal`}, `successor` {`key`, `attempt_id`} and `carry` {`source_attempt_id`, `source_candidate_id`, `candidate_sha`} or {`none`: `requested_none` | `no_candidate`}. No event wakes you for the replace itself; the successor's outcome does.
