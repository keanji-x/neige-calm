Planner-only: cancel one task in the track's plan. A `pending` task is canceled before it starts. A `running` codex or claude task in this Track is canceled and its worker stopped: the kernel interrupts its turn, ends its session and releases its workspace; a report the worker sends afterwards is rejected and delivers nothing. `dispatched` (wait until it is running), `verifying` (wait for `task.gate_result`), terminal-kind, child-track and isolated tasks cannot be canceled; the refusal names the task's current status. Canceling an already-canceled task is an idempotent success. `message` is required and persisted as `agent_message` on the `plan.updated` event. Optional `lifecycle` drives the track state machine in the same atomic write; canceling does not change the lifecycle by itself.
