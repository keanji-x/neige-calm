Planner-only: for status start with detail=summary and the exact key when known; omit key for a compact current inventory. Use detail=full with that key for semantic evidence. Omitted arguments retain the full plan. Summaries are current observations, not acceptance or authority; compare attempt_id when reading full evidence. Gate commands are not echoed (only step names); each entry carries the latest machine gate verdict as `gate_result` (on failure `status_detail` is gate-red / gate-timeout / gate-infra). When `recovery` is an admission refusal (`allowed` false and `code` other than `not_started` / `not_failed`), `recovery.guidance` names the blocking condition, the one supported continuation (`new_task` | `user_recovery` | `wait_for_settlement` | `none`) and `retained`, each field optional: `workspace_path`, `branch`, `last_commit`, `base_sha`, or `removed: true` once the kernel removed the worktree. Read the worker output for a finished task via the runs views. `worktree` (only when the attempt held a workspace lease) carries the worker's lease `path` and `state`, its slice `branch`, and `last_commit` — the latest `worktree.committed` the kernel recorded for that card; a failed auto-commit after an earlier successful kernel commit is indistinguishable from success. `base_sha` is the commit the worktree started from (the repository's HEAD when the attempt was prepared), present for failed attempts too and absent for leases taken before the kernel recorded it. `removed: true` means the kernel has removed that worktree (and its branch) since it was last provisioned — `path` and `branch` are then omitted, `last_commit` stays; `removed: false` means the kernel has not removed it, whatever `state` says (it says nothing about the filesystem beyond that). No event is emitted. `candidate` is given for every current attempt: `binding: "none"` (`reason`: `isolated` | `terminal` | `child_track` | `no_lease`) when this design mints no candidate for it; `binding: "unbound"` (`reason: "legacy_lease"`) when the attempt's lease predates kernel delivery — the kernel neither commits nor pins it; `binding: "bound"` (with `producer_attempt_id`, `base_sha`, `workspace`, `delivery`) when the kernel commits the worktree after the worker's report. `delivery.state`: `not_reported` (the worker is still running; no delivery fact exists), `ended_without_delivery` (the attempt failed before reporting; it will never have a candidate — `attempt_status`, `status_detail`), `pending` (the delivery row exists and has not settled; wait for `task.git_delivery_settled`, do not review or accept), `committed` (a candidate is pinned at `ref`; `candidate_id`, `commit_sha`, `base_is_ancestor`), `no_change` (the candidate OID equals `base_sha`; that is the whole claim — it does not say the worker never committed), `failed` (no candidate; `failure.code` is `workspace_missing` | `provenance_mismatch` | `commit_failed` | `unresolved`, `failure.reason` the evidence, `failure.retry_allowed` whether a retry could succeed — `workspace_missing` never can), `abandoned` (the Planner gave the failed delivery up), `inconsistent` (rows contradict a kernel invariant; nothing here may be accepted). `workspace` mirrors `worktree` for that lease.
