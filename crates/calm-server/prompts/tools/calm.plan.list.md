Planner-only: for status start with detail=summary and the exact key when known; omit key for a compact current inventory. Use detail=full with that key for semantic evidence. Omitted arguments retain the full plan. Summaries are current observations, not acceptance or authority; compare attempt_id when reading full evidence. Gate commands are not echoed (only step names); each entry carries the latest machine gate verdict as `gate_result` (on failure `status_detail` is gate-red / gate-timeout / gate-infra). When `recovery` is an admission refusal (`allowed` false and `code` other than `not_started` / `not_failed`), `recovery.guidance` names the blocking condition, the one supported continuation (`new_task` | `user_recovery` | `wait_for_settlement` | `none`) and `retained`, each field optional: `workspace_path`, `branch`, `last_commit`, `base_sha`, or `removed: true` once the kernel removed the worktree. Read the worker output for a finished task via the runs views. `worktree` (only when the attempt held a workspace lease) carries the worker's lease `path` and `state`, its slice `branch`, and `last_commit` — the latest `worktree.committed` the kernel recorded for that card; a failed auto-commit after an earlier successful kernel commit is indistinguishable from success. `base_sha` is the commit the worktree started from (when the attempt was prepared: the last known commit of the upstream of the branch the repository's HEAD is on — fetched when the attempt was submitted — when HEAD is at or behind it or has no unpushed commits of its own; the repository's HEAD when HEAD is ahead of it, a shallow history leaves the relation unknown, or the branch has no upstream), present for failed attempts too and absent for leases taken before the kernel recorded it. `removed: true` means the kernel has removed that worktree (and its branch) since it was last provisioned — `path` and `branch` are then omitted, `last_commit` stays; `removed: false` means the kernel has not removed it, whatever `state` says (it says nothing about the filesystem beyond that). No event is emitted. `candidate` is given for every current attempt: `binding: "none"` (`reason`: `isolated` | `terminal` | `child_track` | `no_lease`) when this design mints no candidate for it; `binding: "unbound"` (`reason: "legacy_lease"`) when the attempt's lease predates kernel delivery — no candidate is minted or pinned for it: a Codex worker keeps the legacy auto-commit (`worktree.committed`, visible as `last_commit`), a Claude worker gets no kernel commit at all; `binding: "bound"` (with `producer_attempt_id`, `base_sha`, `workspace`, `delivery`) when the kernel commits the worktree after the worker's report; a bound attempt also carries `upstream` {`sha`: the commit, as last known now, of the upstream of the branch the attached checkout is on now (not necessarily the branch the attempt started from), `behind`: how many of its commits `base_sha` lacks} — read-only and advisory (nothing is rebased or refused over it; `behind` > 0 means a task dispatched now starts from newer code), absent when the checkout's branch has no known upstream. An attempt a `calm.task.replace` successor started from a carried candidate also carries `carry` {`receipt_id`, `carry_sha`: the kernel carry commit its worktree started from (its `base_sha`), `upstream_sha`: that commit's parent, the upstream the candidate was merged onto}: `upstream_sha..<candidate>` is the whole change of the lineage and `carry_sha..<candidate>` this round's own work. `delivery.state`: `not_reported` (the worker is still running; no delivery fact exists), `ended_without_delivery` (the attempt failed before reporting; it will never have a candidate — `attempt_status`, `status_detail`), `pending` (the delivery row exists and has not settled; wait for `task.git_delivery_settled`, do not review or accept), `committed` (a candidate is pinned at `ref`; `candidate_id`, `commit_sha`, `base_is_ancestor`), `no_change` (the candidate OID equals `base_sha`; that is the whole claim — it does not say the worker never committed; on a carried attempt it means nothing changed beyond the carry, not that nothing changed), `failed` (no candidate; `failure.code` is `workspace_missing` | `provenance_mismatch` | `commit_failed` | `unresolved`, `failure.reason` the evidence, `failure.retry_allowed` whether a retry could succeed — `workspace_missing` never can), `abandoned` (the Planner gave the failed delivery up through `calm.task.delivery`; `reason`, `task_outcome`: `failed` | `done_unchanged` | `already_terminal`, and the `task_status` observed then), `inconsistent` (rows contradict a kernel invariant; nothing here may be accepted). Every state with a `delivery_id` carries its `ordinal` (1 for the worker's report, +1 per retry); `delivery_id` is what `calm.task.delivery` takes as `expected_delivery_id`. `workspace` mirrors `worktree` for that lease. `verification` (bound attempts) is the gate's state for this attempt: `ungated` (no gate; the `candidate` settlement is all there is to accept), `not_started` (the worker has not reported), `not_admitted` (`verifying` and no gate Operation yet: the delivery has not settled as a candidate — see `delivery.state`), `running` (a gate Operation exists; wait for `task.gate_result`), then the recorded verdict — `passed`, `red` (a step exited non-zero; the only state that means the code was judged and failed), `timeout`, `infra` (the code was not judged: the wrapper never reached a step, a sampling command failed, or the gate was admitted before settlement — `target.kind: "no_candidate"`), `target_mismatch` (the checkout did not match the candidate before the steps, or changed during them — every step result is discarded; `target.evidence.reasons` names `provenance` / `head` / `dirty`; the candidate itself is intact; continue from it with `calm.task.replace`), `unbound` (the verdict checked nothing against a candidate: legacy lease, or a gate frozen or recorded before this check existed), `not_reached` (the attempt ended before a gate ran; `status_detail`), `inconsistent` (a gated `done` row without a verdict). With a verdict it carries `gate_attempt`, `target` (`kind`: `candidate` with `candidate_id`, `commit_sha`, `lease_id` and `evidence` — `refused` {`cwd`, `before`, `reasons`} / `verified` {`cwd`, `before`, `after`, `reasons`} / `unsampled` {`phase`}; `no_candidate` with `reason`; `unbound` with `reason`), `log_path` and `gate_log` (the runs view of the gate log).
