Open a visible Terminal card in your authenticated Track. request_id is required for idempotent creation; format, claim and the wait arguments never enter the idempotency key (claude_permissions does), so a replayed request_id returns the same terminal and runs the wait as asked. program is a /bin/sh -c command line run with the terminal's env; when it exits there is no shell left: omit it (default shell) when you will run several programs, and send commands with input. format=image only when colors, highlighting or layout are needed. Use the returned terminal_id; never use exec to impersonate this tool. wait_for (elapsed|change|signal|text), wait_ms, settle_ms, signal_events, repaint_ms, wait_text and wait_text_absent have calm.terminal.observe's meaning, defaults and validation and run as the open's final observation, after the claim when claim=true (a change wait's baseline is the open or the claim). Start Claude in one call: {"request_id":"…","program":"claude --settings \"$NEIGE_CLAUDE_SETTINGS\"","claim":true,"wait_for":"text","wait_text":["trust this folder","❯"]} returns the trust dialog or the prompt with control held. claim=true claims control in the same call: claim {status: claimed} with control_id and role owner, or {status: unavailable, reason} while the open still succeeded and the waited state is returned. The claim never revokes control held by another client (a replayed open after a human takeover reports unavailable instead of reclaiming). An image that cannot be rendered never fails the open: the text observation is returned with image {status: unavailable, reason} (after a wait, its wait block is an immediate read's). The env carries NEIGE_CLAUDE_SETTINGS, a hooks-only Claude Code settings file: start Claude with claude (or ccode) --settings "$NEIGE_CLAUDE_SETTINGS" so its hooks (session_start, user_prompt_submit, stop, notification, permission_request, session_end, subagent_stop) arrive as observation signals (calm.terminal.observe wait_for=signal). claude_permissions declares what Claude may do without a dialog: edit (globs relative to the cwd, e.g. "**"), bash (command prefixes, e.g. "python3 -m unittest", "git commit"; a trailing wildcard is implied), deny (prefixes refused, e.g. "git push"). Out-of-scope actions still arrive as permission_request signals; git push, git reset --hard, rm -rf, curl, wget, pip install, npm install and edits under .git always prompt; the result echoes the effective rules as claude_permissions.
