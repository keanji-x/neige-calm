Planner (Workers may call it too): expose a dev server you started for this task through calm's preview gateway so the user can see it in the report. The gateway picks a free port from its pool (`CALM_PREVIEW_PORTS`) and proxies it, including HMR websockets, to `127.0.0.1:<target_port>`; the registration belongs to your own Track. Register only a dev server you started for this task. Never register a calm or dev-calm port, or a server that proxies to calm: the gateway connects from loopback, so such a target reaches calm's loopback-only internal routes one hop further (calm's own listen port is refused, anything behind it is not). The dev server must listen on 127.0.0.1. Viewing needs the owner logged in to calm in the same browser on the same host, and works over LAN http only. `key` names the preview within the Track (e.g. `fe`); registering the same key again keeps its port and repoints it to the new target, so re-register after a restart or a dev server move. `title` is a short label. Returns `{key, port, block_hint}`: `block_hint` is the `calm.report.blocks.upsert` payload that embeds the preview in the report. The `preview` block kind is new: if `calm.report.blocks.kinds` does not list it, skip the block and tell the user the port instead. Refusals say why: the gateway is disabled (`CALM_PREVIEW_PORTS` unset), the pool is full (the error names each holder's Track and key), or the target port is refused (privileged, calm's own listen port, or a pool port). Unregister with `calm.preview.unregister` when the dev server stops for good.
