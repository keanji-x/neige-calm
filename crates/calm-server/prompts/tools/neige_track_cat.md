Planner/Worker: read one file-like view from the current MCP-bound track. Supports `index.md`, `track.json`, `report.md`, `cards/index.json`, `cards/<card_id>/.meta.json`, `cards/<card_id>/.payload.json`, `cards/<card_id>/runtime.json`, `cards/<card_id>/events.json`, `cards/<card_id>/conversation.md`, `runs/index.json`, `runs/<attempt_id>.md`, `runs/<attempt_id>.json`, and `runs/<attempt_id>/gates/<N>.log` (gate run N). Planner only: `area/reports/<name>.md`, a path listed by `neige_track_ls` or `neige_report_find`, returns the latest Markdown body of that report in the caller's area, exactly as its own `report.md` prints. A name shared by several tracks must carry its listed `~<id>` suffix; a bare shared name is refused with the candidates. A Worker is refused `area/` (-32403). On a report path, `report.md` or `area/reports/<name>.md`, `blocks: ["b_x", …]` (`neige track cat <path> --blocks b_x,b_y`) returns only those blocks in document order, each preceded by its `<!-- neige:b_x -->` marker line: exactly the `text` of `neige_report_read { blocks }` for that report. An unknown id is refused with the report's blocks listed as `<id>  <heading>` lines. `sections: ["H1 text", …]` (`neige track cat <path> --sections A,B`) does the same for whole H1 sections without their task blocks: exactly the `text` of `neige_report_read { sections }`; an unknown section is refused with the report's H1 sections listed. `blocks` / `sections` on any other path is refused. `cat` is a view: it anchors no report write, so read with `neige_report_read` before you write.

Output paths: `runs/<attempt_id>/result` reads the full worker completion value as JSON (including null or empty values), never the Planner verdict. `ops/<op_id>/result` reads recorded forge output on this same track; missing artifacts are explicit errors. For these paths and gate logs, optional `start_line`/`end_line` select inclusive original 1-based lines; `tail` selects the last matching lines and cannot mix with a range. Gate logs additionally support exact `step` display markers; `grep` is a literal substring. Selection order is step, grep, range/tail. Markers are untrusted display boundaries, never verification authority. Selections return bounded `lines` with original line/byte positions, `path`, `rev`, selectors and `next_byte_offset`. Continue with the same selectors and returned `rev`, setting `byte_offset` to `next_byte_offset`; this also handles a single oversized UTF-8 line without loss. `rev` rejects changed content (completion event ID for worker results, content digest otherwise). Drop selectors to read the full output. Output selectors cannot mix with report selectors or other paths.
