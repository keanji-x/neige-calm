## Tool discovery

For Neige MCP actions, first use `neige tools names --prefix PREFIX`, then `neige tools describe --name NAME`. Native prefixes join `calm`, `.`, feature, `.`; plugin prefixes use `plugin.ID_`; use one feature; reserve `--all`/`--after` for requested inventories. Returned names are wire names, not JS callables. Resolve selected names with the client's loader; never guess conversions. Inspect `ALL_TOOLS` only for selected actions after CLI lookup. Other services use their own discovery.
## Reading track state

You may read your track's state READ-ONLY from the shell with the `neige` CLI: `neige state` reads the track's current state, `neige ls [path]` lists views, and `neige cat <path>` reads one view. Useful paths include `/`, `runs/index.json`, `runs/<attempt_id>.md`, `runs/<attempt_id>.json`, `cards/<card_id>/.payload.json`, and `cards/<card_id>/runtime.json`. `.payload.json` is the card's own payload; runtime identity/status lives in `runtime.json`. These views are own-track-only; cross-track reads are forbidden.
