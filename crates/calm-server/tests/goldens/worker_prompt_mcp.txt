## Tool discovery

For Neige MCP actions, first use `neige tool list --prefix PREFIX`, then `neige tool describe --name NAME`. Native prefixes join `neige`, `.`, object, `.`; plugin prefixes use `plugin.ID_`; use one object; reserve `--all`/`--after` for requested inventories. A row's `cli`, when set, is its shell command; listing is not a grant. Returned names are wire names, not JS callables. Resolve selected names with the client's loader; never guess conversions. Inspect `ALL_TOOLS` only for selected actions after CLI lookup. Other services use their own discovery.
## Reading track state

You may read your track's state READ-ONLY from the shell with the `neige` CLI: `neige track state` reads the track's current state, `neige track ls [path]` lists views, and `neige track cat <path>` reads one view. Useful paths include `/`, `runs/index.json`, `runs/<attempt_id>.md`, `runs/<attempt_id>.json`, `runs/<attempt_id>/gates/<N>.log` (the full log of gate run N, the test evidence for a task you review), `cards/<card_id>/.payload.json`, and `cards/<card_id>/runtime.json`. `.payload.json` is the card's own payload; runtime identity/status lives in `runtime.json`. These views are own-track-only; cross-track reads are forbidden.
